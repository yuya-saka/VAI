## 1. 境界線抽出の3次元化

### 1.1 背景

現状は各スライス単体で4本の境界線を推定している。これを複数スライスにまたがる
「面」として定義・学習することで、

- 3D方向になめらかな推定にできないか
- 特にアノテーションがない範囲への外挿で、構造が崩れないようにできないか
- 横突孔（椎骨側面の孔）周辺で境界線が破綻しにくくならないか

を検討した。

### 1.2 わかったこと

手動でアノテーションした約1,600スライス・280椎体分のデータを使って実測した。

- **面はスライスに対して斜めになっている。** 傾きの中央値は約20°で、面が
  スライスに垂直だという単純な仮定は成り立たない。
- **予測結果をスライス方向に平滑化してもあまり精度は改善せず** 
  既存モデルの出力はもともとスライス方向に十分滑らかで、誤差の主成分は椎体ごとに生じる
  系統的なズレであり、平滑化では解消しないことがわかった。
  → **面として学習しても、アノテーション範囲内の精度向上は見込めない。
  価値があるのはアノテーション範囲外への外挿の安定化。**

### 1.3 現在の方式とのアーキテクチャ上の違い

新しい方式は、モデルの入力・出力・学習の組み立て方そのものを変える。

| 観点 | 現在の方式 | 新しい方式 |
|---|---|---|
| 入力 | スライス画像1枚 | 前後を含む連続した複数スライス（ひとまとまりの範囲）をまとめて入力 |
| 出力 | そのスライス1枚分の境界線の手がかり | まとまり内の全スライス分の手がかりを一度に出力 |
| 学習時のスライス間の一体性 | スライスごとに完全に独立して学習しており、前後との整合性を学習時に考慮する仕組みがない | まとまり内の手がかりを「スライス番号に対してなだらかに変化する形」にあてはめる計算を学習の過程に組み込み、あてはめとのズレ自体を新しい学習目標として追加する |
| アノテーションのない範囲の扱い | モデルの外側で、スライスごとに独立に出した推定値をあとから曲線で補間・外挿する | 複数スライス分のまとまり自体を椎体全体にわたってずらしながら適用し、重なった部分の推定同士を平均する |

現在の方式では、各スライスの推定はあくまで単独で行われ、前後との
つながりは学習後の後処理（補間・外挿）でしか作られていない。
このため、アノテーションから離れるほど「見たことのない範囲を
外側で無理に延長する」ことになり、破綻しやすかった。

新しい方式では、複数スライスをまとめて見る・出すという単位に変えたうえで、
「なだらかに変化しているはずだ」という制約を学習そのものの目標に
組み込む。さらに推定時も、独立推定＋事後の外挿ではなく、まとまりの
範囲を移動させながら適用するため、モデルは常に実際の画像を見た
範囲内でしか推定を行わない構造になる。

### 1.4 学習方式

- 各境界線を、複数スライスにまたがる「向きと位置がなだらかに変化する
  帯（リボン）」として表現する。線の位置・向きをスライス番号に対して
  1次関数（直線的な変化）で表すのが妥当？と仮定。
- 学習には、アノテーションのあるスライスだけでなく前後の連続したスライスも
  まとめて使う。アノテーションが疎らな範囲でも、画像自体は連続して
  存在するため、追加のアノテーションなしでこの方式が実現できる。
- 推定時は、椎体全体をスライドさせながら短い範囲ごとに推定し、
  重なり合った部分の推定同士を平均する。これにより、遠くまで外挿する
  必要がなくなり、常に近い範囲（画像を実際に見ている範囲）からの
  推定で済むようになる。

### 1.5 実装状況

上記の設計に基づき、学習・推論・評価までの一連のパイプラインを実装し、
動作確認まで完了した。**本格的な学習と、以前のベースラインとの
比較評価はこれから行う。**

### 1.6 今後の課題

- 本学習を行う。
- 学習データが椎体の中央付近に偏っているため、椎体の上下端付近では
  精度が落ちる可能性があり、その影響を確認する
- 定量評価に限界があるため、目視確認も評価手段として使う

## 2. 4領域ごとの骨折検出モデル

### 2.1 背景・制約

椎体を4つの領域（前方・左右・後方）に分けて、それぞれで骨折の有無を
検出したい。ただし全データに4領域ごとのラベルを付けるのは現実的でないため、
一部の症例のみ人手でラベル付けし（約270件・160症例分）、これを
残り大多数の「椎体単位で骨折あり／なし」というラベルと組み合わせて
学習する方法を検討していた。

なお、今回は既存のバウンディングボックス情報（骨折箇所を囲む矩形）は
一切使わず、人手でつけた4領域ラベルのみを教師情報として使う方針とした。

### 2.2 モデルのアーキテクチャ構造

椎体単位の骨折有無を判定する既存モデルは、もともと次のような階層構造を
持っている。

1. 椎体を含む一連のスライス画像を1枚ずつ処理し、各スライスから
   画像全体の特徴マップを抽出する（この時点では4領域の区別はまだ無い）
2. その特徴マップを、あらかじめ用意した4領域マスク（画素ごとに
   どの領域に属するかを示す情報）に従って**領域ごとに集計**し、
   4つの領域それぞれの内部スコアを計算する
3. このスコアをスライス方向に集約し、領域ごとのスコアにまとめる
4. さらに4領域分のスコアを集約し、椎体全体としての骨折あり／なしの
   確率を出力する

**4領域マスクはモデルへの入力ではない。** 画像と一緒にモデルへ
読み込ませるのではなく、2の「特徴マップをどう集計するか」という
プーリングの重みとしてのみ使う。マスク自体に骨折の情報は無く、
「どの画素がどの領域に属するか」という区分だけを与えている。

図で表すと次のようになる。

```
             スライス1（画像）                    スライス2（画像）           ・・・
                   │                                    │
                   ▼                                    ▼
             ┌─────────┐                          ┌─────────┐
             │ 特徴抽出 │                          │ 特徴抽出 │            … スライスごとに処理
             └────┬────┘                          └────┬────┘
                   ▼ 特徴マップ（領域の区別なし）          ▼ 特徴マップ（領域の区別なし）
        ┌─────────────────┐                 ┌─────────────────┐
4領域   →│ 領域ごとに集計   │        4領域   →│ 領域ごとに集計   │   ← 4領域マスクを使うのはここだけ
マスク  │ (プーリング)     │        マスク  │ (プーリング)     │     （入力ではなく集計の重み）
        └────────┬────────┘                 └────────┬────────┘
                  ▼                                    ▼
             領域スコア                             領域スコア
           (R1,R2,R3,R4)                          (R1,R2,R3,R4)
                  │                                    │
                  └─────────────────┬──────────────────┘
                                    ▼  スライス方向に集約
                     領域ごとのスコア（R1／R2／R3／R4）
                                    │  ★ ここに詳細ラベルの教師をかける
                                    ▼  4領域を集約
                   椎体全体の骨折あり／なしの確率
                                       ★ ここは従来通り椎体単位のラベルで教師
```

つまり、最終的に出てくる「椎体単位の判定」は、内部的にはすでに
「領域ごとのスコア」を経由したうえで下されている。この構造がもともと
存在していたことが、今回のアプローチの前提になっている。

### 2.3 詳細ラベルを組み込む構造

上記の内部の「領域ごとのスコア」に、人手でつけた詳細ラベル（どの領域に
骨折があるか）を直接の教師信号として追加するのが今回の設計。
モデルの入口（画像）と出口（椎体単位の判定）はそのままに、
内部の中間出力にだけ新しい教師をかける形になる。

- 詳細ラベルがない大多数の椎体は、椎体単位の判定にだけ教師をかける
  （＝従来通りの弱いラベルとして扱う）
- 詳細ラベルがある椎体は、椎体単位の判定に加えて、内部の領域スコアにも
  直接教師をかける（＝詳細ラベルとして扱う）
- 両者は同じ1つのモデルの中で、最初から同時に学習させる。
  先に弱いラベルだけで学習してから詳細ラベルで調整する、という
  二段階の方式は採らない

**今後詳細ラベルを追加していく際も、この「内部の領域スコアに教師をかける」
という接続点は変わらない。** アノテーションが増えるたびに、同じ仕組みに
そのまま追加していけばよく、追加のたびにモデルの構造を作り直す必要はない。
また、将来的に領域ごとの手がかりをより精緻に捉える仕組み（各領域に
専用に注目する機構など）へアーキテクチャ自体を改良する場合も、
この接続点自体は変えずに、内部スコアの計算方法だけを差し替える形で
拡張できるようにしておく方針。


### 2.4 今後の課題

- 上記の構造で学習を行い、位置情報のみのベースラインを上回る精度が
  出るかを評価する
- 効果が確認できた後の課題として、モデル構造自体の改良
  （領域ごとに注目する仕組みの導入）を検討する
