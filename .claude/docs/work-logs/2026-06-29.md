### 技術的な実装詳細

**座標変換 (DICOM bbox → 224×224プレーン座標):**
```python
# DICOM voxel → LPS
lps = image_pos + cx * ps_col * row_dir + cy * ps_row * col_dir
# LPS → 224px (plane_sampling.py の逆変換、cross-axis 注意)
row_px = dot(delta, col_basis) / SAMPLING_PS + HALF_PX
col_px = dot(delta, row_basis) / SAMPLING_PS + HALF_PX
```

**slice_number マッピング (`_build_slice_mapping`):**
- ファイルstem数値を優先キー（`94.dcm` → 94）
- `instance_number` を補助（`setdefault` で上書きしない）
- `classifier_planes.py` の `_slice_index_by_number` と同ロジック

**画像キャッシュ:** `(study_id, level)` → 15枚のPNG bytesをメモリに保持（最大15症例分）

## Region MIL アーキテクチャ設計（確定）

### 背景と動機

既存のattention MILではWSIをpatchに分割してinstanceを定義するが、
本研究では椎体の4解剖学的領域（前左/前右/後左/後右）をinstanceとして定義する。
参考論文（ORACLE-CT, Fang et al., WSAD/DMIL, RSNA優勝解法）を検討し、
頸椎CT特有のデータ特性に合わせた設計を行った。

### 設計上の重要判断

1. **領域ラベルは一切使わない** — vertebra-level fracture label のみで学習
2. **maskは入力画像には適用しない** — CNN feature map上で56×56解像度のmask pooling
3. **7×7は不可** — 実測でR2/R3が0.7×1.1 pixelしかなく情報消失
4. **56×56を採用** — R2/R3でも5.6×9.0 pixel確保（bbox基準）

### 実測データ（50症例×C3/C4/C5、中央plane）

| Region | bbox (H×W px) | @7×7 | @14×14 | @28×28 | @56×56 |
|--------|--------------|------|--------|--------|--------|
| R1 前左 | 40×52 | 1.2×1.6 | 2.5×3.3 | 5.0×6.5 | 9.9×13.0 |
| R2 前右 | 22×36 | 0.7×1.1 | 1.4×2.2 | 2.8×4.5 | 5.6×9.0 |
| R3 後左 | 21×34 | 0.7×1.1 | 1.3×2.1 | 2.7×4.2 | 5.4×8.5 |
| R4 後右 | 91×135 | 2.9×4.2 | 5.7×8.4 | 11.4×16.8 | 22.8×33.7 |

椎体maskは画像全体の約6.2%を占有。

### 確定アーキテクチャ

```
入力: (bs, 15, 6, 224, 224)  ← Stage1と同一 (5ch CT + 1ch vertebra_mask)
     + region_4class (15, 224, 224)  ← pooling用

1. Backbone: EfficientNetV2-S (features_only, pretrained, BN eval固定)
   → 4スケール feature maps
     Stage 1:  48ch, 56×56
     Stage 2:  64ch, 28×28
     Stage 3: 160ch, 14×14
     Stage 4: 256ch,  7×7

2. FPN Neck:
   各スケール → 1×1 conv → 256ch → upsample to 56×56 → concat → 1×1 conv
   → 統合 feature map (256ch, 56×56)

3. Region Masked Pooling (56×56):
   region_4class → adaptive_avg_pool2d → soft mask (56×56, [0,1])
   各region: weighted avg pool → f_r ∈ R^256
   global: GAP → f_global ∈ R^256
   valid flag: 元224×224で領域pixel > 0

4. BiLSTM (per region, 重み共有):
   input=256, hidden=256, layers=2, bidirectional → (bs, 15, 512)

5. Region Head (共有):
   Linear(512→256) → BN → Dropout(0.3) → LeakyReLU → Linear(256→1)
   per-plane logits → valid plane maskで平均 → region logit z_r

6. Region集約: log-sum-exp
   τ = 学習可能パラメータ (初期値1.0)
   z_vertebra = τ · (logsumexp(z_r / τ) - log(n_valid_regions))

7. Global Head (補助パス):
   別BiLSTM + 別Head → z_global

8. 損失:
   L = BCEWithLogitsLoss(z_vertebra, y) + 0.5 * BCEWithLogitsLoss(z_global, y)
   positive_weight = 2.0, LSE部分はFP32強制
```

### Codexレビュー結果（要点）

`.claude/docs/codex/20260629-region-mil-review.md` に完全版を保存。

- **ゼロマスク入力を却下** → full plane CNN + feature map mask pooling を推奨（採用）
- **noisy-or を却下** → log-sum-exp を推奨（採用）
- **BN eval固定** を推奨（採用）
- **region collapse リスク** — 監視指標として argmax分布・entropy・左右反転整合性
- **global auxiliary head** を推奨（採用、λ=0.5）
- **Stage1との比較**: Stage1 backbone + region pooling head 追加が最も合理的な ablation

### Stage2 実装計画

#### 実装方針

- `train_models/stage1/` は変更せず、`train_models/stage2/` を独立した学習パッケージとして作成する。
- CV分割、holdout、DDP起動、AMP、ログ、W&B、early stopping、OOF/test出力はStage1の実装を移植し、Stage1との比較条件を揃える。
- Stage2固有の変更は、`region_4class.npy` のデータ契約、56×56 FPN、region masked pooling、region/global時系列head、LSE集約、region診断出力に限定する。
- `fracture_region_labels.csv` は学習・モデル選択には使用しない。学習完了後のregion score妥当性確認だけに使える評価入力として扱う。

#### Phase 1: Stage2スキャフォールドと設定

1. `train_models/stage2/` にStage1と同じパッケージ境界を作成する。
2. `config/config.yaml` に以下を明示する。
   - backboneとFPN出力チャネル
   - region数、LSTM hidden/layers、dropout
   - LSE温度の初期値・学習可否・下限
   - global loss weight
   - backbone/headの別learning rate
   - region maskの必須条件と欠損時ポリシー
3. 出力先を `train_models/stage2/outputs/{phase}/{name}/` に固定する。
4. 実効config保存、CLIのfold/epoch上書き、ローカル一時ディレクトリ設定をStage1から移植する。

**完了条件:** config読込と出力パス解決のsmoke testが通り、Stage1の出力を上書きしない。

#### Phase 2: データ契約とDataset

1. `collect_items` で `ct.npy`、`vertebra_mask.npy`、`region_4class.npy` の3ファイルが揃う `(study, level)` のみ収集する。
2. shape/dtype/valueを検証する。
   - `ct`: `(15, 5, 224, 224)`
   - `vertebra_mask`: `(15, 224, 224)`
   - `region_4class`: `(15, 224, 224)`、値は `0..4`
3. `excluded_levels.csv` は既存の前処理結果に反映済みであることを前提としつつ、欠損理由と除外件数を起動時に集計表示する。
4. spatial augmentationは15 planeで同一パラメータを使い、CT、vertebra mask、region maskへ同期適用する。
5. horizontal flipまたはtranspose後も解剖学的region IDが正しいよう、変換結果に応じて `R1↔R2`、`R3↔R4` の再ラベル規則を実装する。vertical flipの扱いは画像座標と解剖学定義をunit testで固定する。
6. brightness/noiseはCTだけに適用し、mask値は最近傍補間で保持する。
7. DatasetはCPU側で `uint8` を返し、device転送後にCTのみ正規化する。返却契約は `images, region_masks, label` とし、評価時のみmetadataを付ける。

**完了条件:** augmentation後もmask値が `0..4`、CTとmaskの位置が一致し、左右反転のregion IDテストが通る。

#### Phase 3: モデル

1. `timm.create_model(..., features_only=True)` でEfficientNetV2-Sの4段featureを取得し、起動時に実テンソルのchannel/解像度を検証する。
2. 各featureを `1×1 Conv → 256ch` に射影し、bilinear upsampleで56×56へ揃えてconcat後、`1×1 Conv` で256chへ統合する。
3. region maskは各classのone-hot binary maskを `adaptive_avg_pool2d(56,56)` し、soft occupancy maskを作る。
4. 各region featureは `sum(feature * mask) / clamp(sum(mask))` でpoolし、224×224で1 pixel以上あるregionだけをvalidとする。
5. 15 plane分のregion featureをregion軸へ展開し、重み共有BiLSTMと共有headで4つのregion logitsを出す。
6. global featureはFPN featureのGAPから別BiLSTM・別headへ渡す。
7. vertebra logitはvalid regionだけの正規化LSEで集約し、温度はsoftplus等で正値制約を付ける。LSE計算はAMP外のFP32で行う。
8. backboneのBatchNormは学習中もeval固定し、optimizer groupをbackboneと新規headで分ける。
9. forwardは学習に必要な `vertebra_logit`、`global_logit` に加え、診断用の `region_logits`、`valid_regions`、`temperature` を名前付き構造で返す。

**完了条件:** batch shape、欠損region、全region有効、AMPの各ケースでforward/backwardがfiniteになり、無効regionがLSEに寄与しない。

#### Phase 4: 損失と学習ループ

1. 主損失を `weighted BCE(vertebra_logit, y)`、補助損失を `weighted BCE(global_logit, y)` とし、`L = L_region + 0.5 * L_global` を実装する。
2. `positive_weight=2.0` はStage1と同じサンプル重み方式を使用する。
3. mixup時は画像だけでなくregion maskも同じ係数で混ぜる。soft mask poolingとの整合を保ち、valid flagは混合前2標本の論理和とする。
4. train/validationでvertebra probabilityは `sigmoid(vertebra_logit)` を直接使用し、Stage1の15 logits平均処理は持ち込まない。
5. checkpointはmodel、optimizer、scheduler、epoch、best metric、effective configを保存し、resume可能にする。
6. model selectionとearly stoppingは `val_auroc` を維持し、AUROC算出不能時の扱いを明示する。

**完了条件:** 1 batchのoverfit testでlossが低下し、1 epoch smoke runでcheckpoint・log・OOF予測が生成される。

#### Phase 5: 評価とcollapse監視

1. Stage1と同じoverall/per-level AUROC、AUPRC、F1、閾値最適化、patient bootstrap CIを出力する。
2. OOF/test CSVに `region_1_prob`〜`region_4_prob`、`global_prob`、`temperature`、valid region数を追加する。
3. region collapse監視として以下をepoch単位で記録する。
   - region argmax分布
   - region probability entropy
   - region間logit標準偏差
   - valid region率
   - 学習温度
4. `fracture_region_labels.csv` が存在する場合だけ、手動ラベルに対するregion単位AUROC/AUPRCとtop-k hit rateを別レポートに出す。これはcheckpoint選択に使用しない。
5. 左右反転前後でregion scoreが `R1↔R2`、`R3↔R4` に対応するかを評価するdiagnosticを追加する。

**完了条件:** OOFからStage1比較指標とregion診断が再計算でき、手動ラベル無しでも学習・評価が完走する。

#### Phase 6: 統合検証と実験

1. CPUまたは1 GPUで少数sample・1 epochのsmoke runを実施する。
2. 1 foldでStage1と同一splitを使うことをstudy ID一覧で照合する。
3. GPUメモリ、items/sec、DataLoader待ち時間を計測し、batch size 4/GPUが成立するか確認する。
4. fold 0を完走し、collapse指標とregion score可視化を確認してから5-foldへ進む。
5. 比較表はStage1とStage2でholdout、fold、augmentation、epoch、positive weightを揃え、AUROC/AUPRCとper-level結果を並べる。

**完了条件:** fold 0でNaN、空mask由来の異常、単一regionへのcollapseがなく、Stage1と同一条件の比較可能なOOF成果物が得られる。

#### 実装時に先に固定する注意点

- `timm` のfeature channelはモデル名依存のため、設計値をhardcodeせず `feature_info` と実forwardで検証する。
- transposeは左右・前後の意味を変える可能性がある。region IDの単純swapで解剖学的一貫性を保証できない場合は、Stage2ではtranspose augmentationを無効化する。
- region maskのmixupはsoft mask化されるため、Datasetでは整数mask、mixup後はone-hot soft maskという境界を明確にする。
- 全region無効のsampleはモデル内fallbackで隠さず、データ収集時に除外して件数を報告する。
- Stage1 checkpointのbackbone重みを使うablationは、pretrained ImageNet初期化の基準実験完了後に追加する。
