## セッションB: 骨折bboxアノテーションツールのbbox位置バグ調査（詳細）

### 発端
`Unet/fracture_annotation_tool`（(study, level)ごとに15プレーンを見て4領域の骨折有無を
手動ラベルするローカルWebツール）で、bboxが「スライス位置・椎体レベル・大きさ」の点で
正しく表示されているか検証。結果、**3つの独立したバグ**を発見。うち2つを修正、
最大の1つ（学習データ本体に波及）は次回セッションで再生成込みで修正することに決定。

### バグ①: 椎体レベルの誤割り当て（修正済み）
- **症状**: 同じ骨折bboxが隣接椎体のページにも白枠表示される。
- **原因**: `server.py` が「bboxのスライス位置がそのレベルの `full_range_mm`（椎体マスクの
  z方向投影範囲）に入るか」だけでレベル判定していた。この範囲は**隣接椎体同士で10〜25mm重なる**
  （頸椎1個の高さ15〜20mmに匹敵）ため漏れる。実例 `...10051`: 本来C4のbbox（スライス133-148）の
  133・134がC3の範囲にも入りC3に誤表示。
- **修正**: 前処理パイプラインが計算済みの正式割り当て（メタデータ
  `classifier_planes.planes[].bbox_slice_numbers`）を使う方式に変更。
  - 新規スクリプト `data_preprocessing/rsna_pipeline/build_fracture_bbox_planes.py` で
    各bboxを所属レベルの15プレーン空間（224px、`fracture_dataset` の `ct.npy` と同一幾何）に
    投影し、`data/rsna_data/fracture_bbox_planes.csv` に1 bbox=1行で出力。
    列: `study_id, level, plane_index, slice_number, x, y, width, height, row_min, col_min, row_max, col_max`。
  - `server.py` はこのCSVを `(study, level) → {plane_index: [矩形...]}` にロードして描画するだけに変更
    （独自の範囲判定・座標変換ロジックを全削除）。型エイリアス `BboxPlanes` 導入。
  - 投影座標は旧inlineロジックと**完全数値一致**を確認（割り当てだけ直し、幾何変換は不変）。

### バグ②: プレーンindex(p0-p14)の誤割り当て（修正済み）
- **症状**: `28657/C2` の p0（骨マスクほぼゼロの端プレーン）に本来バラバラなbboxが13個集中。
- **原因**: 「どのプレーンに表示するか」の判定で、生の `slice_position_mm`（スキャナz）を
  各椎体の**傾いたnormalに投影済みの** `plane_positions` と直接比較していた。椎体は断面積最大化の
  ため個別に最大±35°傾く（実データ平均rx≈13°）。回転中心から離れたbbox（Y=-209.6mm等）ほど
  角度×レバーで数十mmずれ、全プレーン範囲外→常に端のp0にcollapse。
- **修正**: `build_fracture_bbox_planes.py` の `_process_study` で、bbox中心の3D点を計算し
  レベル固有の `normal_lps` へ投影してから `argmin` するよう変更（`normal_by_level` を追加）。
  再生成後 `28657/C2` は p7〜p12 に正しく分散（手計算の正解と一致）。全7217行で端プレーンへの
  異常集約が解消。

### バグ③: 多椎体にまたがる骨折の割り当て崩壊（**未修正・次回のメイン**）
- **これが本丸。学習データ本体に波及している。**
- **原因（コア）**: `classifier_planes.py` の `load_study_bbox_centers`（L76-）が、bbox行を
  「スライス番号が連続するか」だけでグループ化（`_contiguous_slice_groups`）し、各グループを
  **代表1スライス（中央）の3D点だけ**で椎体割り当てする。**スライス番号に隙間がなく複数椎体に
  またがる骨折**だと、run全体が1点に潰れて1椎体に集約され、他の陽性椎体はbbox保証を失う。
- **実例 `31077`**: `train.csv` で C3/C4/C5/C6 の4椎体が骨折陽性。しかしbbox行はスライス
  216〜358まで**隙間なく143枚連続** → パイプラインは1グループとみなし代表287（C4-C5境界）だけで
  判定して**143行全部をC5に割り当て**。当初の全レベル最近傍による概算は
  C4-C7への分割だったが、陽性レベル制約を適用したPhase 2の確定結果は
  C3=216-228, C4=229-271, C5=272-317, C6=318-358。
- **定量化（全データ）**: bbox行を1つずつ独立に最近傍椎体へ割り当て直すと、公式のグループ代表
  割り当てと**19.9%（1436/7217行）で食い違う**。40スライス超の異常グループが426中24件。
- **学習データへの波及メカニズム**（`classifier_plane_selection.py` 確認済み）:
  - `select_classifier_plane_positions` は `range_low=min(t_low, *required)`,
    `range_high=max(t_high, *required)` で、割り当てられたbbox位置を必ず含むよう15プレーンの
    範囲を強制拡張する。誤ってC5に混入したbboxがC5の範囲を椎体外まで最大15mm引き伸ばし、
    骨がほとんど写らないプレーンを生む（`sample_classifier_planes` が `bbox_forced` プレーンの
    空マスクを例外的に許容しているのはこの状況の想定）。
  - 逆にC4/C6/C7はbbox保証を失い、15プレーンが単純等間隔選択になる。骨折スライスを飛ばすと
    **陽性ラベルなのに根拠の骨折領域が `ct.npy`/`region_4class.npy` に写らない**サンプルが生じ得る。
  - ※これはコードを読んで導いた「起こりうる」機序。実際の被害件数・精度影響は未測定。

### 現CSVの状態（重要な注意）
`fracture_bbox_planes.csv` は**バグ①②は直っているがバグ③は未修正**。つまりレベル割り当ては
まだメタデータの（グループ代表ベースの）`bbox_slice_numbers` に依存しており、19.9%の行が
間違った椎体に載っている。次回のパイプライン修正＋再生成後に作り直す前提。

## セッションA: stage2 region head vs primary head 統計比較（圧縮版）

stage2 `outputs/ablation/region_only`（primary_loss_weight=0）の結果確認から、
`baseline/v1`・`stage1 v1_parity` との比較を段階的に厳密化したセッション。

- **主要な発見**: baseline/v1 の `metrics.json` は旧schemaでprimary（`pred_prob`）のみ集計され
  region head未評価だった。現行 `compute_metrics` で `region_pred_prob` を再計算。
- **統計手法**: patient-cluster paired bootstrap（`study_uid` 単位, n_boot=2000）を実装。
  同一モデル内primary/regionは誤差相関0.96-0.98で検出力高、別モデル間は独立で検出力低。
- **OOF vs Test の一貫性問題**（ユーザー指摘）: OOFは非アンサンブル・Testはアンサンブルで
  混在比較は不整合。→ Testもfold毎に再推論し非アンサンブル予測を取得（GPU2で全15ckpt再推論、
  5fold平均が既存アンサンブルと相関0.9999で一致）。
- **決定版分析**: OOF+Test per-fold を結合（24,245行・患者2,009人＝全データ）で再bootstrap。
  - **頑健に生き残った唯一の結論**: 「region head > primary head（同一モデル内、AUROC/AUPRCとも
    有意）」。ΔAUROC=+0.0047 [+0.0011,+0.0083], ΔAUPRC=+0.0264 [+0.0167,+0.0369]。
  - region_only の primary 超えというOOFのみの主張は全データで消失（偶然だった可能性大）。
- **コード変更**: `train_models/stage{1,2}/src/trainer.py` のtest推論をアンサンブル平均＋
  **fold単位の非アンサンブル予測**も返すよう修正。`train.py` で `test_predictions_per_fold.csv`
  追加保存。既存pytest全pass。詳細は `.claude/docs/experiments/2026-07-13-stage2-region-vs-primary-comparison.md` 参照。
