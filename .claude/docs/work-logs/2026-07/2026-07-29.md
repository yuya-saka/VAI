## B. Fold 設計の要点（Codex 相談後の確定版）

評価プロトコルは Codex に7問投げて詰めた（`.claude/docs/codex/20260729-stage4-evaluation-protocol.md`）。
**私の当初案は3箇所で誤っており、Codex の指摘で反転させた。**

### B-0. 【訂正1】outer fold は checkpoint 選択からも隔離が必要
当初案「fold の val の弱AUROCで早期停止 → 同じ fold の領域ラベルで OOF 評価」は
**厳密な outer-CV ではない**。弱AUROCと領域性能は相関しうるので、同じ study を
checkpoint選択と領域評価の両方に使っている。
→ outer fold *f* ごとに残り4 fold を inner CV として4回まわし、**inner の弱AUROCだけ**で
epoch を選ぶ（4回の best epoch の中央値）→ 残り4 fold で refit → outer を1回だけ predict。
warm-start も outer fold *f* を学習していない checkpoint に限る。

### B-1. 【訂正2】OOFプールは生確率が primary。rank正規化は感度解析
当初案は rank 正規化を primary にしていたが逆。同じ loss・同じスコア定義から出た確率なら
生スコアが cross-fitted 予測手続きを最も素直に表す。rank正規化は fold 間の実差まで消し、
z-score は根拠のない location-scale 仮定を置く。
順序: primary=生確率プール / SensA=fold内percentile（**参照集合はアノテ済みでなく全bbox-eligible陽性候補**、
ラベルで変換をfitしない）/ SensB=陽性数重みのfold別AP平均 / z-scoreは診断のみ。
primary と SensA の差が **絶対値0.03以上**か候補順位が変わったら「fold-scale sensitive」と宣言。

### B-2. 【訂正3】locked test の残29件を**先に**埋める（私の推奨と逆）
SE の縮み方: test 52→81 は √(52/81)=0.801 で**約20%縮小**、
同じ29件を CV 216→245 に入れても √(216/245)=0.939 で**約6%**。小さい集合に足すほうが得。
→ 順序は ① test 残29 → ② CV 残134 → ③ 全部揃えて最終学習。
ただし81件でも期待陽性は R1≈12/R2≈23/R3≈14/R4≈50 で、R1/R3 は領域別 confirmatory に不足。

### B-3. 【訂正4】「R2を優先してアノテート」は実行不可能かつ禁止
**付ける前にその bag が R2 かは分からない**。bbox の見た目から推測して選べば
ラベル相関の選択になる。許されるのは fold・study ID hash・現fold件数などラベル非依存の順序のみ。
禁止: 推定領域／モデルスコア／不確実性／誤分類／bbox形状による優先、
結果を見た後の追加アノテ、目標達成での打ち切り、事後の難例除外。
途中で止める可能性があるなら fold1 集中は危険 → 残134を `[23,31,33,27,20]` 比例配分で固定乱数抽出。

### B-4. primary 指標の定義と床（実測）
`macro-AP = (1/4)Σ_r AP(y_r, q̄_r)`、non-interpolated AP、閾値を選ばない。
**no-skill 床は領域prevalenceの平均: OOF 0.3507 / test 0.3077**。
always-posterior の exact-set 41%・hit@1 59% は**別指標の床**で、macro-APの床ではない。
正式名: *Study-grouped OOF conditional anatomical-region macro average precision
among bbox-eligible fracture-positive vertebrae*。

### B-5. bootstrap は outer fold 内で層別。**study数は160でなく129**
アノテ済み study 実測: **OOF 129**（fold別 27/24/31/23/24）/ test 31 / 計160。
160 は268 bag全体の値なので **OOF の CI で160をリサンプルしてはいけない**。
outer fold 内で study を復元抽出し fold毎の study 数を固定、10,000 valid replicate、
候補差は paired、陽性/陰性が0になる replicate は引き直し、引き直し率>1% の領域は CI 不安定と明記。

CI幅の見積: OOF macro-AP **0.12–0.22**（半幅±0.06–0.11）/ R2単独 0.20–0.35 /
test macro-AP 0.25–0.40 / test の R1(8)・R3(9) は 0.35–0.60。半幅>0.10 は「方向のみ」。

**陽性study 20未満は領域別 confirmatory 禁止**（実測）:
OOF は R1 56 / R2 36 / R3 49 / R4 83 で**全領域OK**、
test は R1 **8** / R2 **10** / R3 **7** / R4 22 で **R4以外は不可**。

### B-6. region-informed な比較は実質1回まで
安全な比較回数の一般解はない（Cawley&Talbot 2010, Varma&Simon 2006）。2候補でも optimism は出る。
→ **候補の絞り込みは弱OOF AUROCで行う**（差0.005未満なら事前登録の優先順位）。
config・seed・manifest hash を凍結してから領域指標を**一度だけ**開く。
4候補の領域APを見比べて選んだ時点で、その値は **exploratory**。
→ **arena（手順3-5）は明示的に exploratory と宣言し、confirmatory は単一モデルの1回だけ**にする。

### B-7. seed は5個固定。決定量は「平均スコアのプールAP」
seed `[42,43,44,45,46]`、全候補・全foldで共通。bag毎に5確率を平均してからプールしてAP。
当初案「seed毎にAP→平均」は**別のestimand**（平均的単一seed性能）で secondary 扱い。
デプロイするのがseedアンサンブルなら平均スコア側が正しい決定量。
禁止: seedを5倍の観測としてプール、CIを 1/√5 に縮める。

### B-8. その他（変更なし）
fold 単位の領域指標は出さない（R2 が fold1,2 で5件）。
対照: always-posterior、metadata-only（≥0.45で警告）、
`region_mode=global/scramble`（Stage3実装済み）、**SideAcc 75 bag**。**hit@1 は primary 禁止**。
A-3 で z軸の対照を落としたので、**ショートカット耐性の検証は SideAcc がほぼ唯一の砦**。
条件は「点推定 >0.60 かつ study-cluster bootstrap 下限 >0.50」。

### B-9. アノテーション追加後の再実行ルール
評価だけに使うなら再学習不要（ただし**新ラベルを見る前にOOFスコアを凍結**）。
**学習にも使うなら5つのouterモデルを全部ゼロから再実行**（新bagは1 foldで評価例、他4で学習例になる）。
**216ラベル時点と350ラベル時点のOOF予測を混ぜてはいけない。**

### H-1. 仕様により前半の制約が2つ外れた

| 前半で置いた制約 | 本仕様 | 理由 |
|---|---|---|
| 既存分割（seed 42）を凍結 | **作り直す** | 凍結の根拠は「fold-k checkpoint を warm-start に使う」だった。本仕様は**全arm ゼロから学習**、Pretrain-to-Mixed も fold ごとに事前学習し直すので依存が無い |

### H-3. 【最重要リスク】レベルだけで macro-AP 0.458 出る

CT画像を一切使わず椎体レベル（C1–C7）だけで領域陽性率を予測した pooled-OOF AP:

| | R1 | R2 | R3 | R4 | macro |
|---|---|---|---|---|---|
| prevalence（no-skill）| 0.291 | 0.220 | 0.269 | 0.590 | 0.342 |
| **level-only** | 0.473 | 0.269 | 0.408 | 0.682 | **0.458** |

レベル別陽性率が大きく違うため。特に **C2 は R1 73% / R4 19%** で、
C3–C7（R4 62–79%）とほぼ別タスク（歯突起骨折の分布）。

椎体レベルは画像から自明なので、モデルはこの 0.458 をタダで得る。
→ **level-only を必須の対照 arm に追加**（仕様には無い）。**合格ラインは 0.342 ではなく 0.458**。
C2 を含む/除く macro-AP の両方を出すことを推奨。

  人手ラベルは `Stage3Output.region_evidence_logits`（面集約後の `q[r]`）に付く。

### H-5. 【要注意】陰性の領域教師が二重にかかる

仕様は「陰性が多すぎると領域予測が全部陰性へ倒れる」ことを警戒して `L_region` の陰性をサンプリングするが、
**既存の `L_negative` は 9,665 陰性 bag 全部に対して `p[z,r]` を0へ押している**。
`q[r]` は `p[z,r]` の集約なので、実質的に全陰性が領域出力を抑制済み。
サンプリングで制御できるのは新項だけで旧項は野放し。
→ A(既定: lambda_neg 0.1 のまま) / B(L_negative も同じサブセットに限定) / C(lambda_neg を下げる) を試せるようにする。
学習中の各項の実効値と勾配ノルム比を必ず記録。

### H-5b. Codex 相談で決着した具体値

`.claude/docs/codex/20260729-stage4-mixed-supervision-design.md`（7問）。

| 項目 | 決着 |
|---|---|
| held-out test | **不要**。患者単位CVは正式な内部検証(TRIPOD)。160患者から更にtestを割くより全員をOOFに使う方が効率的 |
| Weak-only vs Mixed を confirmatory にする条件 | 10個。核心は**「差は `λ_region=0` だけ」**（同一fold/seed/初期値/sampler/陰性ID/aug乱数/更新回数）と**outer foldをcheckpoint選択に使わない＝早期停止を切って固定epoch** |
| 陰性サンプリング比 | **1:1**（214 strong に対し 214）。2:1は過剰（strong内にも領域陰性が多数ある）|
| 陰性の抽出 | **毎epoch再抽出・復元なし・C1-C7完全一致・1患者1bag優先・seed=42+epoch・manifest保存**。run全体で固定した214 bagは禁止 |
| クラス重み | **陰性を足した後**に計算。`w_r=min((2N_A−P_r)/P_r, 8.0)` → R1 5.87 / R2 8.00 / R3 6.44 / R4 2.39。足す前の `[2.44,3.54,2.72,0.70]` は使わない |
| λ_region | `0.25+0.75·min(e/4,1)`（epoch1=0.25 … epoch5以降=1.0）。**標本数比10,700:216をλに掛けてはいけない**。step1で0.25>0なので「最初から同時」に違反しない |
| λ_neg | **0.05** 一定（現行0.1から下げる）。本実装の `L_negative` は plane-level なので `L_region` と二重計上ではない。もし q-level にするなら λ_neg=0 |
| 椎体 safety gate | **非劣性マージン −0.010 AUROC**（患者paired 95%CI下限）。補助で AUPRC Δ≥−0.020。Fail時の独立ヘッド追加は**新しい事前登録実験**であって同じarmの修正ではない |
| 水平flip | **確率0.50で維持**。1回のflipで image / mask / **mask ID 2↔3** / **target y[R2]↔y[R3]** / **region-valid フラグ R2↔R3** を同時swap。主推論ではTTAしない |
| flip の必須テスト | ①double flipで完全復元 ②R2のみ合成→flip後R3のみ ③学習100件でmask IDとlabelの不一致0件、1件でも学習停止 |
| Detail-only | 小標本の弱さは交絡でなく介入の一部。ただし主張は「弱ラベル症例を**追加する**価値」に限定。**Weak-only-size-matched**（214 annotated を弱ラベル扱い+214陰性）を統制armに追加して三角測量 |
| fold層別 | CP-SAT/MILPが理想だが、懸念の核心は「モデル性能を見てsplitを選ぶな」。本実装は分布均衡のみが目的関数でモデル出力を見ていない。**hard constraint（各fold各領域で陽性≥8かつ陰性≥8）と領域targetを全充足**（実測確認済）。hashして凍結し作り直さない |

**endpoint coupling の6故障**: gradient conflict / winner amplification / compensatory inflation /
calibration shift / annotation-subset shortcut / multi-region under-reward。
100 step ごとに勾配cosine（中央値<−0.20が2epoch連続で警告）、勾配ノルム比（>3.0）、
pooling weight偏り（1領域>0.95が全体の>80%）等を記録する。

### H-6. 次セッションの実装順序

1 `--no-bbox` commit → 2 データ層（領域ラベル結合、`region_supervision` 3値）
→ **3 水平flip の R2↔R3 ラベル swap ＋テスト** → 4 fold を `stage4_folds.csv` ベースに
→ 5 level-only 対照（CPU数分）→ 6 `stage4_loss` → 7 層別サンプラ
→ 8 Weak-only と Mixed-from-scratch を5-fold → 9 pooled OOF ＋患者単位bootstrap
→ 10 Detail-only と Pretrain-to-Mixed

**手順3を飛ばさないこと。静かに壊れる唯一の箇所。** マスクだけremapしてラベルを放置すると
左右が反転し、例外も出ないまま R2/R3 の主張が逆になる。
