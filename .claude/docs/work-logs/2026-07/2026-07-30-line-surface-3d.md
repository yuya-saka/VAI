# 2026-07-30 作業ログ（Unet 線学習の3D面化）

Stage4 とは別件。`Unet/` の線推定を、スライス単体ではなく複数スライスにまたがる
「面」として学習する方式を検討し、**実装仕様の決定まで**を行った。実装は未着手。

**結論**: スラブ（連続Nスライス）単位で、4本の線をそれぞれ
**(角度, ヒートマップ重心) を z の1次で表したリボン**として学習する。
追加アノテーションなしで、既存の2D PNG だけで完結する。

設計の詳細は `.claude/docs/line-surface-3d-design.md`、
図解は `.claude/docs/line-surface-explain.png`。

---

## 1. 出発点（ユーザー提示）

- 現在はスライス画像単体で線を抽出している
- 複数スライスにまたがる線同士を面と定義し、3D方向になめらかな線推定にしたい
- 外挿時も構造を保てる可能性がある
- 検討ポイント：面はスライスに直交するのか斜めになるのか / 重ねたものを面として学習できるか

---

## 2. 前提の確認：スタックは3Dとして整合している

`data_preprocessing/segmentation_dataset/extract_slices.py` の `extract_oblique_slice()` は
**椎体ごとに1組の傾き (rx, ry) とボリューム中心**を使い、`k` だけを変えて断面を切る。
スライスごとの再センタリング・再回転は行っていない。

→ 1椎体のスライス群は単一の剛体フレームを共有し、そのまま積めば正しい3Dになる。
ボクセルは 0.4mm 等方なので「1スライスあたりの px 変化」＝ tan(傾斜角)。

---

## 3. 実測（手動アンカー 1,618枚 / 284椎体）

### 3.1 面はスライスに直交しない

傾斜角 = arctan(dρ/dz) の分布：

| | median | p90 | max |
|---|---|---|---|
| line_1 | 17.0° | 45.2° | 85.2° |
| line_2 | 21.4° | 47.0° | 74.2° |
| line_3 | 17.5° | 42.2° | 86.6° |
| line_4 | 23.2° | 50.2° | 73.1° |

傾きの標準誤差は約3.8°。median 約20°の傾斜は実在する。**直交拘束は誤り。**

### 3.2 面は線織面なので3Dボクセル学習は不要

各スライスの境界が直線という現行前提を保つ限り、面は
`x·cosφ(z) + y·sinφ(z) = ρ(z)` と **z の1次元関数だけ**で決まる。
3D U-Net でボクセルを塗る必要はない。

### 3.3 4本の線は連動していない / junction は滑らか

- 椎体をまたいだ dφ/dz の線間相関はほぼゼロ（-0.23〜0.02）
  → 単一の大域変換で連動させる設計は不可
- junction（line_1∩line_2 等）の z 方向 LOO 予測誤差は1次で median 1.08px
  → 実在の安定ランドマーク

---

## 4. 重要な否定的知見：z方向の平滑化では精度は上がらない

既存2Dモデルのテスト予測（6,473本線）を椎体×線ごとに z で平滑化し直して GT と比較：

| | 生の予測 | z 1次平滑化後 | z 2次平滑化後 |
|---|---|---|---|
| 角度誤差 median | 3.66° | 3.62° | 3.63° |
| ρ誤差 median | 2.80px | 2.85px | 2.86px |

**ほぼ不変。ρ はむしろ悪化。**
理由は、現行モデルの出力が既に z 方向に十分滑らかだから（1次フィットからの乖離が 0.65°/0.40px）。
0.4mm 間隔の隣接スライスはほとんど同じ画像なので、平均化で消える独立ノイズが乗らない。

誤差を分解すると：

| | 椎体×線ごとのバイアス | 帯内のばらつき |
|---|---|---|
| 角度 | median 3.03° / RMS 5.23° | median 1.74° / RMS 3.50° |
| ρ | median 2.73px / RMS 6.24px | median 1.19px / RMS 6.11px |

主成分は椎体ごとの系統的バイアスで、平滑化で消える種類ではない。

→ **「面にすれば帯内の精度が上がる」という期待は成り立たない。価値は外挿にある。**

## 6. 外挿の破綻を実測（GT不要で定量化できた）

「定量評価はできない」のは GT 比較に限った話で、**領域が形成できたか否かは GT なしで測れる**。
`dataset_zprop/gt_masks` を全 21,507 スライス再集計：

| | スライス数 | 領域欠損 |
|---|---|---|
| 帯内（manual/interpolated） | 1,980 | **0 (0.0%)** |
| 帯外（extrapolated） | 19,527 | **2,814 (14.4%)** |

内訳（4領域の名前は body / right_foramen / left_foramen / posterior）：

| 領域 | 面積0 | 率 |
|---|---|---|
| right_foramen | 1,423 | 7.3% |
| left_foramen | 1,236 | 6.3% |
| body | 752 | 3.9% |
| posterior | 102 | 0.5% |

アンカー帯からの距離別：

| 距離 | 欠損率 |
|---|---|
| 0-2.8mm | 0.8% |
| 3.2-6.0mm | 6.4% |
| 6.4-9.2mm | 20.6% |
| **9.6-12.4mm** | **28.8%** |
| 12.8-15.6mm | 18.5% |

**横突孔領域の消失が失敗の主成分（13.6% / 14.4%）。ユーザーの問題意識は数値で裏付けられた。**

### 補足：現行外挿はそもそも滑らかでない

zprop の伝播パラメータの2階差分は平均 |d²φ| = 1.05°、|d²ρ| = 1.48px、
**隣接スライス間の最大変化は median で 15.0° / 14.3px**。
cubic spline 伝播のはずが帯内GTのLOO残差（1.8°/1.2px）と比べて桁違いに粗い。

### 目視でも確認

`sample1/C4`（アンカー z=49-56、全域 z=17-89）で伝播線をCTに重ねた結果、
z=64 (conf 0.45) で線が飛び出し始め、z=72 (0.20) で約45°暴走、z=80 (0.10) で完全破綻。

## 7. 横突孔：今回は使わない（ユーザー決定）

検討はした（結果は設計書の第2部に残す）：

- 椎体マスクは中身が埋まっており横突孔は穴として取れない（87%のスライスで穴ゼロ）
- CT濃度からは取れる（マスク内部の低濃度連結成分の最外側左右2つ、帯内100%/帯外74.8%）
- junction との位置関係は横突孔間距離で正規化して std 0.051〜0.085（実寸6〜10px）
- ただし椎体海綿骨の低濃度部を大量に拾うノイズが多く、そのままでは実用に足りない

> **ユーザー決定: 横突孔は現時点では使わない。今後アノテーションするかもしれないが今はしない。**

## 8. 決定した仕様

### 8.1 データ構成

| | |
|---|---|
| 画像 | **全 z に密**。21,507枚、椎体あたり median 71枚 = 28.4mm（`dataset_zprop/images/`） |
| 教師 | 中央の帯のみ。1,618枚 / 284椎体（`dataset/lines.json`） |
| 座標系 | 椎体ごとに tilt・中心が固定 → そのまま3Dとして積める |

- `dataset_zprop/images/` は `dataset/images/` と**ピクセル単位で一致**することを確認（311枚照合、不一致0）
- **zprop の擬似ラベル（lines.json）は使わない**
- アノテーションの z は 148/284 椎体で非連続。だが画像は密なので
  **入力スラブは連続で取り、損失はラベルのあるスライスにだけ掛ける**

学習単位（ラベル付き3枚以上を含む窓）：

| 窓 N | 幅 | 学習スラブ数 | 推論スラブ数(stride1) |
|---|---|---|---|
| 9 | 3.6mm | 2,708 | 19,235 |
| **15** | **6.0mm** | **4,370** | **17,531** |
| 21 | 8.4mm | 6,031 | 15,827 |

### 8.2 面の表し方：リボン（角度 + 重心）

**ρ は使わない。** 理由：

1. `utils/losses.py:199` の `rho = (nx*cx + ny*cy)/D` が示す通り、
   ρ は重心を法線方向へ射影しただけの派生量で、線に沿った方向の情報を捨てている
2. 評価で見るのは**角度誤差と重心誤差**であり、パラメータをそれに合わせるべき（ユーザー指摘）

線1本につき次の4量をそれぞれ z の1次で表す：

```
cx(z)     = cx0 + u·Δz
cy(z)     = cy0 + v·Δz
cos 2α(z) = p0  + p1·Δz        Δz = z - スラブ中心
sin 2α(z) = q0  + q1·Δz
```

= 8係数 / 線、4本で **32係数**でスラブの全構造が決まる。

- cx0, cy0, α0：スラブ中央での線分の位置と向き
- u, v：リボンの傾き（1スライスあたりの重心移動 px）
- p1, q1：リボンのねじれ（1スライスあたりの回転）

角度を doubled-angle の2成分に分けて別々に1次フィットする。
フィット後に正規化して `α = atan2(q, p)/2`。

### 8.3 1次で良いことの実測（重心座標で再検証）

GTヒートマップを実際に生成して重心と主軸角を取り、椎体×線708件で測定。

帯内（median 2.8mm）の実際の動き：重心 median 4.38px (p90 7.46)、角度 median 5.61° (p90 12.07)

leave-one-slice-out：

| モデル | 重心誤差 px (median/p90) | 角度誤差 deg (median/p90) |
|---|---|---|
| 定数 | 1.78 / 3.12 | 2.34 / 5.03 |
| **1次** | **1.50 / 2.88** | **1.95 / 5.39** |
| 2次 | 1.65 / 4.20 | 1.96 / 7.41 |

**1次が最良。2次は p90 が悪化して過学習。** (φ, ρ) で測ったときと同じ結論。

### 8.4 モデルと損失

`ResUNet` は `in_channels` / `line_channels` が config 引数なので、
`in_channels = 2N` / `line_channels = 4N` とするだけで 2D のままスラブを扱える。
3D conv 化は次段階。

リボンフィットは新しい回帰ヘッドを足さない：

1. 各スライスの予測ヒートマップから `_compute_moments_batch` で `cx, cy, nx, ny` を取る（実装済み）
2. `cos2α = nx²-ny²`, `sin2α = 2·nx·ny`
3. 4量をスラブ全体で z の1次回帰（閉形式・微分可能）

損失：

| 項 | 適用 | 中身 |
|---|---|---|
| 既存ヒートマップ損失 | ラベルのあるスライス | 局所証拠 |
| 角度損失 | ラベルのあるスライス | フィット値の (cos2α, sin2α) vs GT |
| 重心損失 | ラベルのあるスライス | フィット値の (cx, cy) vs GT の px 距離 |
| リボン外れ罰 | **スラブ全スライス** | 各スライスの生の4量とフィット値の差 |

角度損失・重心損失がそのまま評価指標と一致する。
リボン外れ罰だけラベル不要で全スライスに掛かり、これが面としての一体性を作る。

### 8.5 必須の注意点

- **augmentation をスラブ内で揃える。** 現行の aug はスライス独立。
  スラブ内で回転・スケールがバラバラだと面が壊れて学習が成立しない。
  `A.ReplayCompose` を既に使っているので1枚目の replay を残りに適用すればよい。
- 直接パラメータ回帰は過去に不安定だった形跡がある（config の `use_line_loss: false`）ため、
  実績のあるヒートマップ経路を残す。

### 8.6 推論

椎体全高をスラブでスライディング（stride 1〜3）し、重なりを平均して大域のリボンにする。

**長距離外挿が不要になるのが本質的な改善点。**
現行は3.6mmのアンカー帯から±12mmを画像を見ずに外挿しているが、
スライディングなら各位置で実際の画像を見るので外挿距離は常に窓の半分（3〜4mm）以内。
重なり位置での不一致はそのまま GT不要の信頼度指標になる。

## 9. 実装で踏むと分かっている地雷

φ は [0°, 180°) 周期なので、線が 0/180° をまたぐと φ が飛ぶと同時に **ρ の符号が反転する**。
図の作成中に実際に踏んだ：sample3/C5 で素朴なフィットが
傾き -1.01px/slice（傾斜45°）と誤答（正解 +0.12px/slice = 7°）。

**帯内で φ が 0/180° をまたぐ椎体×線は 42/1108 件（3.8%）、38椎体。**

→ 8.2 の重心 + doubled-angle 表現ならこの問題は最初から発生しない。

## 10. 期待できること / できないこと

**できる**
- 帯外の領域欠損（14.4%、10-12mm地点で28.8%）を減らす
- 伝播パラメータの非平滑性（隣接スライス間で最大15°/14px）を構造的に排除

**限界（正直に）**
- 訓練スラブは全て椎体中央（マスク面積最大位置）由来。
  椎体上下端の見た目は訓練で一度も見ていない → ドメインシフトは残る
- ただし追加アノテーションなしで到達できる最善

**評価**（すべて GT 不要）
- 帯外の領域欠損率（ベースライン 14.4%）
- スライディング窓の重なり不一致
- 冠状断・矢状断リフォーマットでの目視

## 11. リフォーマット可視化（実証済み）

面を z 軸を含む平面で切ると、交線は z ごとに1点の**曲線**になる。
つまり冠状断・矢状断のリフォーマット画像上では、各境界面が1本の曲線として全高にわたって見える。

実際に `sample1/C4` で作成して確認済み。スライスごとの overlay では見えない
「面が椎体全高でどう走っているか」が1枚で判定でき、アンカー帯は短いセグメントとして写る。
定量評価が限られる以上、これが実質的な目視評価手段になる。
