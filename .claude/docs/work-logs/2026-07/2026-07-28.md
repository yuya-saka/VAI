## 3. 【重大】bbox強制plane によるリーク（実測・確定）

`classifier_planes.build_classifier_plane_plan` は `select_classifier_plane_positions` に
bbox アンカー位置を **required position として渡している**（`classifier_planes.py:210-223`）。
つまり15面のうち数面が「病変を含むと分かっている位置」に固定される。

全13,432 bag の `processing_metadata/*.json` を集計:

| グループ | bag数 | bbox強制planeを持つ | 割合 | 平均強制plane数/15 |
|---|---|---|---|---|
| **アノテーション済み** | 268 | **268** | **100.0%** | 1.20 |
| 陽性・未アノテーション | 1,173 | 172 | 14.7% | 0.18 |
| 陰性 | 12,643 | 0 | **0.0%** | 0.00 |

**局在ベンチマークにしたい bag だけが 100% の割合で病変位置由来のサンプリングを受けている。**
このまま `fracture_dataset` で局在評価すると、実運用と比較不能な楽観値になる。
Codexも両相談で独立に同じ指摘をしている。**ここを直さない限り他の実験に意味がない。**

なお強制plane の有無が陰性と完全に分離している（0%）ため、椎体分類 AUROC 0.921/0.937 も
厳密にはリークフリーな基準値ではない。**Stage1 も bbox盲データで取り直す必要がある。**

## 4. 【朗報】bbox盲サンプリングでも病変被覆は維持される（実測）

「bbox強制を外すと病変がサンプリングされなくなるのでは」という最大の懸念を事前検証した。
各アノテーション bag で bbox アンカーを外した plane 選択（robust range 上の均等15面 + max_area位置のみ必須）を
再計算し、実際の bbox アンカーが最近傍planeからどれだけ離れるかを測った。
各planeは `channel_offsets_mm = [-1.25,-0.625,0,0.625,1.25]` すなわち **±1.25mm を撮像している**。

- plane間隔（robust range / 14）: 中央値 **1.61mm**（min 0.98 / max 2.75）
  - 間隔 ≤2.50mm すなわちチャンネルが連続被覆する bag: **259/268**
- bboxアンカー→最近傍bbox盲plane の距離: 中央値 **0.39mm** / p75 0.60 / p90 0.76 / max 8.40
- **全アンカーが ±1.25mm 以内に収まる bag: 263/268 = 98.1%**（いずれか1つ以上なら 266/268 = 99.3%）
- 外れは2件のみ（`20928/C6` 8.40mm、`19808/C2` 2.76mm）。robust range 外にアンカーがある bag が6件

**結論: bbox盲データへの作り直しは病変可視性をほぼ失わない。** リーク除去のコストは
実質2件の脱落のみ。GPUを使う前に最大リスクが1つ潰れた。

| 領域 | 面あたり中央値(px) | 平均(px) | ピーク面(px) | stride4特徴グリッド換算(cell) | 領域が空の面 |

| left_foramen | 135 | 253 | 466 | 29.1 | 143/600 |

椎間孔は入力224x224上で概ね 12x12px 相当、FPN融合先（stride 4 → 56x56）で約30 cell。
極端に小さくはないが、**FPNは stride 32 まで融合しており実効受容野は椎間孔よりはるかに広い**。
マスク内平均プーリングをしても空間的特異性は保証されない（Stage3が出力を
"contextual evidence" と呼んでいるのはこの理由で正しい）。
また椎間孔は **面の21-24%で存在しない** ため、region_valid の扱いが効いてくる。

## 6. Codex相談の結果

### 相談1（既存Stage3に強教師を足す前提）
`.claude/docs/codex/20260728-region-label-model-design.md`

- regime は **(b) staged semi-supervised**。fold毎の weak-only checkpoint から warm-start し、
  global batch 16 = strong-pos 4 / weak-pos 4 / neg 8 で約20 epoch fine-tune。
  backbone LR 2e-5 / head LR 1e-4、mixup OFF
- 損失は **非対称**に付ける:
  - `q[r]` には 0/1 完全な4領域多ラベルBCE（クラス重み `w_r=clip(n_r0/n_r1,1,4)`）
  - `p[z,r]` には **人手が0と付けた領域のスライスにだけ 0 教師**（陽性領域の全スライス=1 は誤り。どの面に骨折があるか不明）
  - `L = L_bag + α(t)L_q + 0.25α(t)L_strong_neg + 0.1L_neg_bag`、`α(t)=min(1,(t+1)/5)`
  - 層別サンプリングで bag loss が歪むので `L_bag=(2N+·mean+ + N-·mean-)/(2N+ + N-)` に変更
- **最初はアーキテクチャを変えない**（強教師の効果とアーキ変更を交絡させない）。
  重み共有BiLSTM維持、free attentionには戻さない、normalized-LSE維持、region-presence branch不要。
  次点は zero-init region embedding `f'=f+e_r` のみ
- **R4は正当なクラスとして維持。分割も除外もしない**（既存R4=1を再分配できない／R4=0は貴重な真陰性）
- primary metric = アノテーション陽性bag上の **4クラス macro-AUPRC**（study単位 cluster bootstrap 10,000回）。
  hit@1をprimaryにしてはいけない（R4固定で約59%当たる）
- kill基準: 強教師後も bbox盲 held-out macro-AUPRC が weak-only を 0.05 上回らず、
  かつ masked が global/scramble を上回らないなら、この4領域マスクでの局在主張は中止

### 相談2（白紙アーキテクチャ前提）
`.claude/docs/codex/20260728-clean-slate-localization-architecture.md`（全文保存済み）

- 主モデルは **region-query head**: 4つの解剖同定クエリが各planeの高解像度FPN特徴へ cross-attention。
  `region_4class` は **hard pooling ではなく attention への加算 soft bias** に降格（マスク外への注意を許す）
- z方向は共有の小さな temporal module + 別の gated-attention head で集約
- **Stage1流の global 椎体ヘッドを別経路として保持**（非劣性ガードレールを局在集約に巻き込まない）
- fold対応の **Stage1 checkpoint で初期化**、まず query head のみ学習（encoder凍結）、
  凍結ゲートを通ったら late stage のみ joint fine-tune
- **Stage3 の hard mask pooling は「必須の低コスト baseline」であって新モデルの既定ではない**
- 根拠: hard poolingは検証されていない生成マスクに従って境界特徴を不可逆に割り当て、
  病変を領域面積に比例して希釈する。posterior 62% vs 椎間孔 6% では特に危険。
  強教師は識別性問題を解くが、**平均で捨てた空間情報は復元しない**
- 解像度について: 「224x224 @0.4mm がボトルネックだと示されたわけではないが、
  stride4プーリングは1-2pxの皮質断裂を消しうる」

追加の重要点（全文から）:

- **希釈の定量**: mask平均プーリングでは、骨折特徴が k px・領域面積 A_r のとき pooled feature への寄与は
  `Δf_r ∝ k/A_r`。posterior は椎間孔の約10倍面積なので**同サイズの骨折信号が約10倍希釈される**
- soft mask prior の具体形: `π = (1-ρ)·M̃/ΣM̃ + ρ/|Ω|`、`a = softmax_u[(W_q e_r)ᵀW_k F_z(u)/√d + β·log(π+ε)]`、
  初期値 ρ=0.15 / β=1.0（0〜2で学習）/ ε=1e-6。mask prior は25%でdrop、2-4px の erosion/dilation も加える
- **(C) mask-free heatmap は trap**（4領域bagラベルでは領域内部の形状が非同定。CAMらしい絵が出ても証拠にならない）。
  (D) 3D は 15-plane visibility 診断が落ちた場合の次案。(E) は**Stage1の最終1280-D pooled特徴では空間情報が無い**ので
  中間 stride-2/4 の spatial map を凍結して使うなら有用
- **(B) 採用の撤回条件を明示**: B が A を macro AP で +0.03 上回らず、mask perturbation にも強くならないなら
  **正直に A を採用する。その場合 rewrite は無駄**
- **guardrail は region noisy-OR ではなく独立 global head で取る**。非劣性マージンは絶対値 -0.02
  （study-cluster bootstrap の 95%CI 下限で判定。Stage1 TEST 0.937 に対する点推定基準なら 0.917）
- Stage1 の augmentation（vertical flip / ±45°回転 / permutation）は**局在には強すぎる**ので作り直す

### 2本の関係と、実際の合流点
矛盾ではなく順序の問題として整合する。**両者とも「bbox強制plane の除去が先」で独立に一致**しており、
そこは実測（§3, §4）でも裏付けられた。

さらに相談2の **Step 2 が両者を1つの安い実験に合流させる**: fold対応 Stage1 encoder の
stride-2/4 特徴を**一度cacheして、head だけを学習**し、同一特徴上で

- E: global-pooled + 4 logits
- **A: Stage3 の hard mask pooling + 教師領域損失**（＝相談1の推奨そのもの）
- B0: query、mask priorなし
- B1: query、soft mask priorあり

を比較する。head-only なら 5-fold でも encoder 5-fold 再学習よりはるかに安い。
**「作り直すべきか」を GPU を大量に使う前に実測で決められる。**
