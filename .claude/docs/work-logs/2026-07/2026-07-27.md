## 2. 骨折椎体の見落としを発見（本題）

ユーザー指摘「骨折bboxがあるはずの椎体に、bboxが無いことになっていないか」を受けて
`train.csv` の椎体別骨折ラベルとツールの実run構成を突き合わせ。

- **骨折ラベル=1なのにrunが1つも無い椎体: 25件 / 235 study**
- 原因: 前処理metadataの `assigned_bbox_slice_numbers` がDICOM z範囲だけで椎体を
  割り当てるため、頸椎が湾曲し隣接椎体のz範囲が重なる箇所でbbox行が別椎体へ
  誤って割り当てられる（例: study 19778 で C4 mask z=[169.4,192.9] と C5 mask
  z=[152.9,179.4] が10mm重複）。
- 全235 study・全7,217行 × 7椎体の被覆率総当たりで内訳を確定:
  - 割当level == 最大被覆level: 6,247行 (86.6%)
  - 不一致だが最大被覆levelにも既存runがある（別runに紛れているだけ）: 374行 (5.2%)
  - **不一致かつ最大被覆levelにrunが無い（見落とし本体）: 487行 (6.7%)**
    - うち骨折ラベル=1（真の見落とし）: **9件・40行**
    - うち骨折ラベル=0（骨折していない椎体への単純なはみ出し）: 92件・447行
  - どのmaskにも被覆0: 109行（うち復元不可16件との重複は0件、新規見落とし無し）
  - mask欠損/空だった椎体: 0件（25件全てmaskは存在・非空10万〜41万voxel）
- 残る **16件は該当bboxが1行も無い**（RSNA元データの欠損、ツール側では復元不可）

# セッション2: axial表示向きの左右整合性検証

## 問い

DICOMアノテーションツールで「画像上の見た目の右／左」で椎間孔骨折をラベル付けしている。
生DICOMの表示と、処理後データ（`bbox_centered_dataset/ct.npy`）の表示向きが変わっていたら、
左右が入れ替わってラベルが無意味になる。その恐れがあるか。

## 結論: 反転の恐れなし。現行ラベルをそのまま使用可（ユーザー決定）

### 検証1: 座標写像の全数チェック（決定的）

処理後画像の端が生DICOM画像のどちら側に対応するかを、全 536 run / 8040 断面で計算。

| 検査 | 結果 |
|---|---|
| 処理後の右端 → 生DICOMでも右側 | 8040 / 8040（反転0件、最小マージン 125.2 px） |
| 処理後の下端 → 生DICOMでも下側 | 8040 / 8040（反転0件、最小マージン 114.0 px） |

境界すれすれの症例すら無い。

### 検証2: 実画像相関による独立照合

パイプライン（`plane_sampling`）を一切使わず、pydicom + DICOMヘッダのみから
「アノテーターが見ている画像」を再構成し `ct.npy` 中央断面と相関（20 run抽出）。

- 19/20 で無反転（identity）が最良。`identity - fliplr` 平均 +0.187
- 例外1件 `10678/C1` は相関自体が0.14でtilt過大により判定不能（検証1では正常）
- スクリプト: `.tmp/.../scratchpad/verify_orientation.py`（永続化せず）

### 構造的に反転し得ない理由

- `process_study.py:112-117` — 断面基底は**そのDICOMシリーズ自身のIOP**
  （`geometry.row_direction` / `column_direction`）を出発点にしている
- `orientation.py` `_corrected_basis` — 補正は Euler `"XY"` の傾き回転のみ。
  **法線（Z）まわりの回転が無い＝鏡映も面内回転も数学的に起こり得ない**
- 実測: `dot(断面row_basis, DICOM row_direction) >= 0.951`、column側 `>= 0.819`

両ツールとも **画像右＝患者左、画像上＝腹側**（放射線科標準）。
RSNA 2012 study中 2004件が `IOP=(1,0,0,0,1,0)` の標準axial。

## 副次的に判明: R2/R3 の日本語呼称だけが患者基準では逆

`REGION_NAMES`（`Unet/line_only/rsna_4region_segmentation/constants.py`）と
両ツールUIの「R2 右椎間孔 / R3 左椎間孔」は患者基準では逆。class2は常に画像右＝患者の左。

原因は領域マスクを作る線検出モデルの**学習元データが逆向き**だったこと:

- `data_preprocessing/segmentation_dataset/convert_to_png.py:340,352` が
  `ct_data[:,:,k].T` → `flipud`。元NIfTI affine は `diag(0.4)` の RAS なので
  **列＝RAS +x＝患者右**（神経放射線慣習）
- 実PNGとの相関で確認（無反転 0.877 / 鏡像 0.362、k=49で一致）
- 院内 `lines.json` の line_1/2（right_foramen）は平均x≈140/158＝画像右
  → **院内データ内では命名は正しい**。RSNA断面はその鏡像なのでズレる

線検出モデルは学習時と左右反転した入力に適用されている（mirror domain shift）。
頸椎はほぼ左右対称のため class2/class3 は常に左右の孔へ正しく分離しており、破綻はない。

## 人手ラベルはマスクと index 整合済み（remap不要）

`fracture_region_labels_dicom.csv`（本セッション時点 285行 / 160 study）を
`bbox_corrected_occupancy.npy` × `region_4class.npy` と突合:

| 人手ラベル | mask class2優勢 | class3優勢 | 重なり0 | bbox平均col |
|---|---|---|---|---|
| R2のみ陽性 (43行) | **33** | 2 | 8 | 154.4（画像右） |
| R3のみ陽性 (58行) | 2 | **47** | 9 | 62.2（画像左） |

アノテーションは「画像上の見た目の左右」で付けられており、`region_4class` の
class2＝画像右 と一致。**`region_k` 列 ↔ mask class k で対応済み、学習時のremapは不要。**

plane側 `fracture_region_labels.csv`（overlay表示あり）も同じ対応（4/5一致、1件は要確認）。
