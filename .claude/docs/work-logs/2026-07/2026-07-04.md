# 2026-07-04 Work Log

## Stage1 `v1_parity` fold2 クラッシュの原因調査・修正

`outputs/baseline/v1_parity` の学習がfold2の11epoch目、validation中に
`sklearn.metrics.roc_auc_score: ValueError: Input contains NaN` で停止。
fold0（74epoch, early stop）・fold1（75epoch）は正常完走していた。

### 原因

`train_models/stage1/src/trainer.py` と `train_models/stage2/src/trainer.py` を
直接比較し、stage2にはある「non-finite loss/勾配のfail-fast機構」がstage1には
一切無いことを特定。Codexにセカンドオピニオンを依頼し確認
（`.claude/docs/codex/20260704-nan-stage1-trainer.md`）。

- stage2: `torch.isfinite(loss)`チェック、`scaler.unscale_`→`clip_grad_norm_`→
  `isfinite(gradient_norm)`チェック、非有限勾配は`max_consecutive_amp_skips`回まで
  スキップ許容後に`FloatingPointError`で停止。AMP dtypeは`bfloat16`を明示。
- stage1: これらが無く、`scaler.step/update`のみ。AMP dtypeも暗黙のfloat16
  （autocastのデフォルト）のまま。
- Codexの見立て: 「BatchNorm running statsの汚染」単体が最有力ではなく、より広く
  「fp16 autocast下でforward側の非有限値が無検知で通過している」ことが根本。
  fp16はbf16よりダイナミックレンジが狭く、overflowに弱い。

### 実装内容（Claudeが直接実装、Codex委譲なし）

1. `train_models/stage1/src/trainer.py`:
   - `_amp_settings()`追加（stage2と同じBF16安全チェック付き）。
   - `_train_epoch`にstage2と同じnon-finite loss/勾配ガードを移植
     （`scaler.unscale_`→`clip_grad_norm_`→`isfinite`チェック→
     `max_consecutive_amp_skips`超過で`FloatingPointError`）。
   - `_validate`に非有限確率の検知を追加。`val_items`と同順であることを利用し
     study_uid/vertebraを特定してfail-fastさせる（sklearnまで伝播させない）。
   - `_collect_oof_predictions`/`predict_on_items`（OOF・test推論経路）にも
     同様の非有限値検知を追加。
   - **重要なバグ発見**: BF16化後、`torch.sigmoid(logits).cpu().numpy()`が
     `TypeError: Got unsupported ScalarType BFloat16`でクラッシュすることを
     smoke testで発見（numpyはbf16非対応）。stage2の`.float()`キャスト箇所
     （`slice_logits = output.slice_logits.float()`）を参考に、3箇所の
     sigmoid計算前に`.float()`キャストを追加して修正。
2. `train_models/stage1/config/config.yaml`:
   - `amp_dtype: "bfloat16"`, `gradient_clip_norm: null`（stage2 parity同様
     クリッピング自体は無効のまま診断機構だけ入れる）, `max_consecutive_amp_skips: 8`
     を追加。
3. ユーザー指示「途中からでもできるようにしろ」を受けて、fold単位の再開耐性を追加:
   - `save_fold_artifacts()`: fold完了ごとに`fold{N}/metrics.json`・
     `fold{N}/oof_predictions.csv`を保存。
   - `load_or_reconstruct_fold_artifacts()`: 保存済みならロード、
     未保存（このセッションの修正前に学習したfold0/1のような場合）でも
     `best_model.pt`が残っていればcheckpointの`val_metrics`とOOF再推論から
     自動復元し、次回のために書き戻す。
   - `train_models/stage1/train.py`の集計ロジックを、「今回のプロセスで学習した
     fold範囲だけ」から「`range(0, n_folds)`全体をディスクから読み直す」方式に
     全面変更。これにより`--start_fold 2 --end_fold 4`のような部分実行でも、
     fold0/1を含めた5fold通しのOOF/test集計・最終結果表示が出るようになった。

### 検証

- 新規ロジックの単体テスト（bf16/fp16両経路の`_train_epoch`/`_validate`、
  非有限loss/勾配/確率のfail-fast、`save/load_or_reconstruct_fold_artifacts`の
  キャッシュヒット・None復帰・実チェックポイントからのbackfillをすべて
  合成データ+実モデルでend-to-end確認）。
- 既存テストスイート10件・ruff（trainer.py分は新規コード含め全てクリーン、
  train.py側の既存lint崩れ7件は元々スコープ外のまま不変）。
