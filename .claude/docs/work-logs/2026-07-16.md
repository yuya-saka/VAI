## Stage3 学習実装

### モデルと損失

- direct classification headを置かず、FPN特徴から4解剖領域のevidenceを抽出する。
- slice内attention、region pooling、instance pooling、vertebra poolingの階層構造を実装した。
- weak labelだけで学習し、領域別・slice別evidenceを推論時に保存できる。
- deterministic spatial-scramble controlを実装した。
- parity設定ではStage1/2と同じ学習条件を維持し、安全設定だけgradient clippingを有効化できる。

### 実行基盤

- YAML configで使用GPU番号を指定できる。
- `mp.spawn` を使ったDDP学習に対応した。
- CNN/FPNはBF16、階層headとpoolingはFP32で実行する。
- NFS上のデータをローカルscratchへstagingしてから学習できる。
- early stopping、AUROC-best checkpoint、model/optimizer/scheduler continuationを実装した。
- fold開始・終了範囲は `data.start_fold` / `data.end_fold` / `data.n_folds` の必須設定とし、
  不正範囲を明示的に拒否する。旧 `end_fold=4` のsilent defaultは削除した。

### W&B

- rank 0だけがW&Bへ記録する。
- config surfaceはStage1と同じ次の3項目だけに統一した。

```yaml
wandb:
  enabled: true
  project: null
  run_name: null
```

- `project` / `run_name` がnullの場合だけ、実行側で既定値を導出する。
- loss内訳、validation metrics、optimizer group別LR、patience、fold bestを記録する。

- 固定test用DataLoaderと推論経路を追加した。
- 学習済みfoldを使うsingle-fold test推論と、複数foldのensemble test推論を実装した。

## 分割・checkpoint再現性ガード

### split manifest

- `split_manifest.csv` を各experiment rootへ保存する。
- duplicate `(study, vertebra)` rowを拒否する。
- train_val/test間のstudy overlapが0であることを検証する。
- 全行がtrain_valまたはtestのどちらか一方へ完全に分割されることを検証する。
- train_valの各行がvalidation foldへちょうど1回だけ割り当てられることを検証する。
- resume時は既存manifestとの完全一致を必須とする。

### 旧出力の拒否

- fixed holdout導入前の出力は `split_manifest.csv` がないためresumeを拒否する。
- エラーは、旧Stage3 protocolのため再学習が必要であることを明示する。
- rootの保存済みconfigは、既存foldの再開時だけでなく、同じexperimentへ未学習foldを追加する場合も
  現在configとの整合性を検証する。異なるhyperparameterのfold混在を防ぐ。

### checkpoint protocol

- `STAGE3_DATA_PROTOCOL_VERSION = 2` を導入した。
- checkpointへ次を保存する。
  - epoch
  - architecture version
  - data protocol version
  - data manifest SHA-256
- 旧protocol checkpointと、dataset membershipが変わったcheckpointのloadを拒否する。
- 実際の旧 `best_model.pt` が拒否されることを確認した。

### seedとresumeの制約

- fold開始時に `random_seed + rank` でseedをリセットし、foldを単独実行した場合と連続実行した場合の
  初期乱数依存を除去した。
- model/optimizer/schedulerの継続は可能。
- persistent DataLoader workerのRNG stateはcheckpointしていないため、resume後のaugmentationと
  batch orderingはbitwise exactではない。この制約を設計書へ明記した。

## 未実装の評価ハーネス

以下は学習・通常test推論とは別の、Stage3の科学的go/no-go評価に必要な比較自動化である。

### paired Delta AUROC

- Stage1とStage3を同一test caseで対応付ける。
- study-cluster paired bootstrapでDelta AUROCと95% CIを算出する。
- 設計上のnon-inferiority基準例は、95% CI下限が `-0.01` より大きいこと。

### fixed specificity

- specificity 90%または95%などを固定したときのsensitivityを比較する。
- test labelでthresholdを最適化せず、validation/OOF側でthresholdを決めてtestへ適用する必要がある。

### 3-seed stability

- 同じfold/configを3 seedで学習する。
- AUROCだけでなく、region winner一致率、attention分布、slice rankingなどevidence assignmentの
  安定性も比較する。

### horizontal flip equivariance

- 左右反転時にbody/posteriorは同じ意味を保ち、left/right foramenは交換されることを確認する。
- vertebra prediction自体が大きく変化しないことも検証する。

### global / scramble controls

- global control: 同じFPNと4 slotを使うがanatomical region maskを使わない比較モデル。
- scramble control: region面積とvalid patternを維持しつつ空間位置をずらす比較モデル。
- Stage3の改善が単なるcapacity増加ではなく、正しい解剖位置に依存するかを検証する。

### 現時点の解釈

baseline学習と固定test評価は実行可能になった。ただし上記ハーネス未実装のため、
「contextual evidenceが解剖学的に意味を持つ」と結論する段階ではない。
