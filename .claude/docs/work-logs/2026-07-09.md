# 2026-07-09 Work Log

## Stage2 region-masked MIL head の主張整理と次実験方針

Stage2 `v1` の region head について、現時点で主張できる範囲と、次に必要な
実験を整理した。目的は以下の2点を安全に主張できる形にすること。

1. **MIL head は椎体レベル骨折分類に有効**
2. **region evidence 表示は VAI スクリーニングに有用な可能性がある**

ただし、bbox から region-level fracture label を作る検証は今回の範囲外とし、
今後の課題に置く。

## 現時点の解釈

- Stage2 primary head は Stage1 互換経路で、region mask を直接見ない。
- Stage2 region head は FPN feature を region mask で pooling し、plane 内の
  4 region を Noisy-OR して椎体ラベルで弱教師あり学習する。
- そのため、これは「primary head を改善するマルチタスク学習」というより、
  **anatomy-constrained weakly supervised MIL classifier** として解釈する方が
  正確。
- 既存結果では、Stage2 内部で region head は primary head より AUPRC/F1 が高い。
  一方、primary head 自体の改善は限定的で、マルチタスクによる primary 改善は
  まだ主張しない。

## 安全な主張案

> Region-masked MIL head は、global primary head よりも椎体レベル骨折分類で
> 高い性能を示した。さらに、解剖学的 region ごとの weakly supervised evidence
> を提示できるため、VAI スクリーニングにおける注意領域提示の可能性がある。

避けるべき表現:

- 「領域ごとに骨折を同定できる」
- 「region head により primary classifier が改善した」
- 「region score は解剖学的骨折確率である」

現時点では、region score は **calibrated anatomical probability** ではなく
**weakly supervised evidence** として扱う。

## 次に必要な実験

### 1. Fair final test evaluation

現在の `metrics.json` の test 指標は primary `pred_prob` で計算されているため、
region head 用の test 指標を正式に出す。

- Stage1 primary
- Stage2 primary
- Stage2 region head

を同一 holdout test set で比較する。

主要指標:

- AUROC
- AUPRC
- patient-level bootstrap 95% CI
- 差分 CI

補助指標:

- F1
- precision
- recall
- Brier score

注意点:

- test 上で F1 最大閾値を選ぶ値は optimistic なので、論文・報告の主結果には
  使わない。
- threshold は OOF/validation で決め、test には固定適用する。

### 2. Screening operating point evaluation

VAI screening では F1 最大点よりも、実運用上の operating point が重要。

候補:

- specificity 90% / 95% 固定時の recall
- recall 90% / 95% 固定時の precision
- false positive per patient / per vertebra
- negative として除外できる割合
- workload reduction

この評価で、region head が「骨折を見逃さずに確認対象を絞れるか」を示す。

### 3. MIL / region mask 有効性の ablation

「MIL 学習が椎体分類に有効」と言うには、単に head を増やした効果や parameter
増加ではないことを切り分ける必要がある。

最小必須 ablation:

1. 現行 joint model: `primary_loss_weight=1`, `region_loss_weight=0.5`
   - 現在の `primary + region` multitask / auxiliary MIL 条件。
   - primary score と region score の両方を評価する。
2. region-only: `primary_loss_weight=0`, `region_loss_weight=1`
   - 最終的に region head だけを使う分類器として成立するかを見る。
   - 「MIL head 自体が椎体分類に有効」という主張の中心になる。
   - 現コードには `primary_loss_weight` がないため、loss 実装を最小拡張する必要がある。
3. primary-only with same architecture: `region_loss_weight=0`
   - region branch を持つが region loss を入れない対照。
   - head 追加・FPN追加・parameter増加ではなく、region-MIL supervision が効いたかを切り分ける。
4. Stage1 primary baseline
   - 既存 Stage1 互換 baseline。
   - architecture 差を含む実用比較として使う。

上記4条件を最優先とする。これで、

- joint multitask が良いのか
- region-only が良いのか
- primary-only では足りないのか
- Stage1 baseline に対してどれだけ改善したのか

を切り分ける。

追加の機序切り分け:

1. shuffled region mask
   - mask の解剖学的位置情報を壊す。
   - 正常 mask より落ちれば、region prior の有効性を支持できる。
2. global FPN head
   - FPN を使うが region pooling しない。
   - 改善が FPN 由来か、region-masked MIL 由来かを切り分ける。
3. Noisy-OR ablation
   - region Noisy-OR ではなく単純平均または max pooling。
   - 現在の MIL aggregation が妥当かを確認する。

可能なら追加:

- parameter count を揃えた extra head baseline
- shared encoder stop-gradient / detached region branch
- `lambda_any` sweep

### 4. Region evidence の VAI 可能性評価

bbox から region label を作らない範囲で、region evidence がスクリーニング補助に
使えそうかを示す。

定量:

- positive/negative 別の region score 分布
- argmax region 分布
- entropy / collapse diagnostics
- false positive / false negative の region evidence パターン
- high-confidence positive の region evidence concentration

定性:

- bbox-positive 症例に限定した可視化例を提示する。
- CT + 4-region overlay + region score + projected bbox を並べる。
- ここでは bbox を label 作成には使わず、視覚的 sanity check として使う。
- 成功例だけでなく、failure case も示す。

可能なら:

- 医師または研究者による小規模 review
- region evidence が確認部位の絞り込みに役立つかを Likert 評価

## 実装セッション: ablation 実行基盤の構築（同日追記）

上記の最小必須 ablation（1〜4）と、追加の機序切り分けのうち global FPN head（条件5）を
実際に config だけで回せるようにする実装を行った。Codex への委譲は行わず、Claude が
直接 Edit/Write で実装（ユーザー明示指示）。

### 1. `primary_loss_weight` の追加（region-only ablationの前提）

- `train_models/stage2/utils/losses.py::stage2_loss` に `primary_loss_weight`
  （デフォルト1.0）を追加。`total = primary_loss_weight * stage1_loss +
  region_loss_weight * region_loss`。
- `primary_loss_weight=0` で primary lstm/head への勾配が厳密にゼロになることを
  ユニットテストで確認済み（`0 * stage1_loss` の自動微分特性を利用。branchを削る
  必要はない）。
- `train_epoch`/`evaluate`（`trainer.py`）に配線済み。

### 2. `selection_metric` の追加（重要なバグの事前潰し）

- 既存コードはチェックポイント選択・early stoppingが primary の AUROC 固定だった。
  region-only条件（primary_loss_weight=0）でこれを放置すると、選択基準が
  **学習されていない primary head のノイズ**になってしまう実質的なバグだった。
- `training.selection_metric: "primary" | "region"` を追加し、
  `_resolve_selection_probability_key()` で解決。不正値は `ValueError`。
- fold単位・OOF・test の `metrics.json` は常に `primary`/`region` 両方の
  metrics を含むよう変更（`train.py::_primary_and_region_metrics`）。
  region maskは常にmodelへ渡されるため `region_pred_prob` は常に計算可能。

### 3. config構成の集約

- 当初 `ablation_joint.yaml`/`ablation_region_only.yaml` を作ったが、
  「学習のたびに有効configが自動保存されるので専用ファイルは不要」という
  ユーザー指示により削除。**`train_models/stage2/config/parity.yaml` 1ファイルを
  手動編集して回す**運用に統一。
- `parity.yaml` ヘッダーに条件1〜5の設定値一覧を明記（joint / region-only /
  primary-only / Stage1 baseline / global FPN head）。
- `config.yaml`（test_v2、チューニング済みレシピ）は意図的に分離したまま
  （`.claude/docs/stage2-consistency-audit-2026-07-01.md` C2/C3 の指摘通り、
  differential LR・gradient clipping・mixup調整等をMIL比較に混入させないため）。

### 4. global FPN head ablation（条件5）の実装

- `Stage2Model` に `region_mode: "masked" | "global"` を追加（`model.py`）。
  - `"global"`: FPN融合特徴を region mask で4分割せず、plane全体をそのまま
    global average poolingして1本の特徴ベクトルにする。primary経路が
    「全plane無条件で使う」のに合わせ、`region_plane_valid`/`plane_valid` は
    常にTrue。同じ `region_head` モジュールを再利用（n_regions=1として）。
  - `region_masks` の中身に完全に不変であることをテストで担保
    （`test_global_region_mode_ignores_region_mask_content`）。
- 4領域決め打ちだった箇所を動的region数対応に修正:
  - `evaluation.py::region_names_for()` を新設。4領域なら従来通り
    `REGION_NAMES`、それ以外は `region_0` 等にフォールバック。
  - `compute_region_diagnostics` の entropy正規化（`/math.log(n_regions)`）は
    `n_regions=1` だと `log(1)=0` で**ゼロ除算になるバグ**があったため、
    1領域時はNaNプレースホルダーに短絡させるよう修正（実装前に発見・修正）。
  - `trainer.py::evaluate()`/`predict_ensemble()` も `REGION_NAMES` 固定依存を
    排除し、実データから動的にキーを決定するよう修正。
- `parity.yaml` に `model.region_mode` を追加、ヘッダーに条件5として明記。
- 条件1〜4は `region_mode: "masked"`（デフォルト）のまま変更不要。差分軸は
  loss weight のみ。`region_mode` を変えるのは条件5だけ。

### 5. 学習速度の実測と `channels_last` 導入

- 実機（DLBox-Alpha、RTX A6000×3、GPU1/GPU2は他ユーザーのCycleGANジョブが
  占有中でGPU0のみ使用可、CPU 32コアも共有）で1epoch=6分の遅さを報告。
- ダミーテンソルでGPU計算のみを実測し、**データローディングではなくGPU計算が
  律速**（602.9ms/step、pure-GPU-compute epoch推定5.39分 ≈ 実測6分）と判明。
  region/FPN分岐が602.9msのうち約195ms（32%）を占めることも確認。
- `channels_last` メモリフォーマットを導入（`model.py::forward` の
  `flattened` テンソル、`data_utils.py::create_model_optimizer_scheduler` の
  モデル生成）。
- 実測: 602.9ms → 395.3ms/step（**約34%短縮**）、GPU計算のみのepoch推定
  5.39分 → 3.54分。変換前後で出力値が完全一致することも確認済み
  （`torch.testing.assert_close`, atol/rtol=1e-4）。
- Tensor Core搭載GPU全般（Volta以降）で有効、A6000固有ではない。
  RTX 4000 Ada（Ada Lovelace, Tensor Core搭載）でもコード変更なしで有効。

### 6. 運用上の注意点（実行時に判明）

- `train.py` は `--config` を省略すると `config/config.yaml`
  （test_v2チューニングレシピ）がデフォルトで読み込まれる。`_base: parity.yaml`
  経由で `experiment.phase` は継承するが `experiment.name` は
  config.yaml側の値（"test_v2"）で上書きされるため、**ablation条件のつもりが
  チューニングレシピと混ざった状態で実行されてしまう事故が起きやすい**。
  → 必ず `--config train_models/stage2/config/parity.yaml` を明示すること。
- `reject_unresumed_reuse` により、同じ `experiment.phase`/`name` の
  出力ディレクトリに training history が残っていると `--resume` なしでは
  即エラーになる（安全装置として正しい挙動）。
