## 1. 素朴な overlap 集約の問題を実データで特定

`bbox_corrected_occupancy.npy` × `region_4class.npy` を素朴に集約する方式を
全514 scored runで検証し、そのままでは使えないことを確認した。

- **inside_fraction 平均0.30 / median0.28**: occupancyの約70%が椎体mask外。
  out-of-plane(z)は3%のみで、ほぼ面内はみ出し。region_4classと
  vertebra_maskは同面積なのでmask過小が原因ではない。
- **posterior top-1 が74.9%**（body20.8 / foramina各2.1）と極端に偏る。
- 原因は複合:
  1. maskのposterior領域面積が0.62（body0.26 / foramina各0.06）という
     大きなcatch-all → 面積priorによる偏り。
  2. posterior優勢runは body→posterior軸へ centroid +39px はみ出し
     （非posterior runは+5px）= bboxが椎体後方（棘突起等）へ実際にはみ出し。

### 最重要の発見: posterior は残余catch-all

`data_preprocessing/segmentation_dataset/generate_region_mask.py` L151:

```python
posterior = mask & (~body) & (~right_foramen) & (~left_foramen)
```

posteriorは「body/foramenでない残り全部」を吸収する残余領域。これが面積62%・
posteriorラベル75%の構造的原因であり、**2Dを3Dにしても直らない**（領域の意味定義の問題）。

面積正規化（enrichment `mass[r]/area[r]`）を試すと posterior top-1 が
73% → 47%、foramina 各2% → 各15-18% に変化し、33%のrunで top-1 が入れ替わる。
posterior優勢の大半は「残余が大きいだけ」の人工物と確定した。

## 2. 3Dネイティブ方式の採用（ユーザー確定）

「15枚の2D argmax maskを積んで積分」ではなく**最初から3Dで**作る方針。
領域segは作り直さず、既存の連続場を3D評価する（ユーザー選択）。

3D部品は全てLPS基準で揃っている:

- **bbox 3D立体**: `BboxCell`（`bbox_geometry.py build_bbox_cells`）
- **椎体3Dボリューム**: `segmentations/{study}/vertebrae_{level}.nii.gz`
- **領域連続場**: `SDFBoundaryInterpolator`（4境界線のcos/sin/ρをz方向にnp.interp、
  各SDFはx,yに線形 → 任意3D点で評価可）

`generate_region_mask` はTLS＋per-plane cv2 canal補正を含むためplane単位で
実行し、fine z-grid上で3D積分する構成とした。

## 3. プロトタイプ実装・20例検証

`Unet/line_only/rsna_4region_segmentation/prototype_3d_soft_label.py` を実装。
fine z-grid（0.5mm、椎体robust_range ∪ bbox支持範囲）上で
NIfTI 3D椎体seg・bbox 3D envelope・線境界SDF場を評価して3D積分する。

多様な20例（posterior/body/foramen優勢、低-高 inside_fraction）で実行:

| 検証項目 | 結果 |
|---------|------|
| 座標整合QC | **20/20例で完全一致**（vertebra_mask_iou=1.0000, center_diff_mm=0.000000, bbox_occ_relative_diff=0.0000） |
| inside_fraction_3d | mean=0.351 / median=0.244（旧2D版mean0.30と同水準） |
| γ振り(enrichment指数) | raw→γ=1で posterior top1 10→5, body 7→4, left_foramen 2→8（flip 0→8/20） |

主要な知見:

- **座標変換の実装は既存の536-run QC済みパイプラインと数値的に同一**と確認。
- **inside_fractionは3D化しても改善せず**: mask外70%弱はbbox自体が椎体segより
  粗いという幾何学的事実で、2D argmaxの離散化artifactではない。
- **entropyベース信頼度重みは危険**: inside_fraction_3d=0.00なのにα entropy=0
  （1領域へ完全確定＝見かけ高信頼）の実例を3例確認。重みはcoverage/inside_fraction
  ベースにすべき。
- **γ=0.5を推奨、γ=1.0は暴走**: `6620/C2` は左右孔のraw shareがほぼ対称(0.074/0.075)
  なのに、左孔の体積が右の1/3というだけでγ=1では right0.133 vs left0.386 へ乖離。
  γ=0.5はposterior偏りを是正しつつこの暴走を避ける。

## 4. mask外の扱い（ユーザー確定）

**mask外のbbox寄与は完全に不使用（inside-only）**。fine z-grid上で
vertebra_mask>0の範囲のみ領域評価し、mask外bboxは常にmass寄与ゼロ。
inside_fractionの低いrunはlabel_weightで自動的に信頼度を下げる。
SDF最近傍attribution（案B）は実装しない。

## 5. 全件生成の方針を確定（AskUserQuestionで3点決定・実装は未着手）

1. **2段分離構成**: 重い3D積分は生の積分値のみ保存
   （`mass[r]` / `volume3d[r]` / `inside_fraction_3d` / `total_occ_mass` /
   `n_planes` / `bbox_row_count` / `geometry_mode`）。
   α（raw/enrichment）・γ・label_weightは軽い後段で何度でも再計算する。
   → γを生成時に焼き込まない。γ変更に重い再実行が不要。
2. **stability当面省略**: 最初のテーブルは mass/volume/inside_fraction のみ。
   label_weight = inside_fraction_3d × informativeness(1-H(α)/log4)。
   stabilityは後付け不可だが、必要になれば専用パス再実行で追加可能。
3. **サンプル抽出QC**: 全件でなく約30 run で alignment QC。

### 実装計画（次にやること）

- **Stage A**（`generate_..._integrals.py`）: 重い3D積分 → 生積分テーブル
  `data/rsna_data/bbox_region_soft_label_integrals.csv` + manifest。
  native_dicomのみ、mask外寄与ゼロ、サンプル30run alignment QC。
- **Stage B**（`shape_..._labels.py`）: 生テーブル → 最終ラベル
  `data/rsna_data/fracture_region_soft_labels.csv`。
  α=enrichment(γ既定0.5)、label_weight=inside_fraction×informativeness。γはCLI引数。
- 前回書きかけた一括版 `generate_bbox_region_soft_labels.py`（γ・weight式・CSV列を
  焼き込む設計・rejected）は破棄し、2段構成で書き直す。

## 6. 骨折領域アノテーション方式を元DICOM直接表示へ変更（ユーザー確定）

骨折領域（R1 body / R2 right foramen / R3 left foramen / R4 posterior）の
手動判定は、bbox中心補正15断面ではなく、**元DICOMスライス上で直接確認する方式**を
正式なアノテーション経路として採用する。

今後のR1-R4手動ラベルは、すべて `Unet/dicom_bbox_annotation_tool` で作成・更新する。
既存の `Unet/fracture_annotation_tool`（bbox中心補正15断面方式）は、生成形状や
領域maskを確認するための**可視化・QC専用**として残し、アノテーション入力や
ラベル生成には使用しない。実装は両者を分離したままとする。新方式の表示仕様は以下。

- CTは元DICOMの行列サイズ・向きのまま固定bone window（W=2000 / L=400）で表示。
- `train_bounding_boxes.csv` の `x, y, width, height` はリサイズ・再投影せず、
  元DICOMピクセル座標へそのまま赤色で描画。
- 椎体レベルは再推定せず、`processing_metadata/*.json` の
  `assigned_bbox_slice_numbers` に保存済みの確定割当を使用。
- DICOM系列上で連続するbbox行を、既存bbox-centered datasetと同一の
  `run_XX` 単位に分割（235 studies / 536 runs / 7,217 bbox rowsで完全一致）。
- 割り当てられたC1-C7の最大連結成分3D maskを元DICOM平面へ最近傍投影し、
  **水色半透明maskの上に赤bbox**を描画。これにより割当椎体とbbox位置を同時確認する。
- レンダリング画像とmask volumeはbounded memory cacheのみで扱い、画像ファイルは保存しない。
- 手動判定結果だけを既存ラベルと分離した
  `data/rsna_data/fracture_region_labels_dicom.csv` へrun単位で保存。

### この方式を採用する理由

全7,217 bboxを元DICOM座標でC1-C7の処理済み3D maskへ照合した結果、bbox座標の
直接描画自体は整合していた一方、現在の椎体割当には目視確認が必要な例が存在した。

- 6,244 / 7,217行（86.5%）: 割当椎体maskとの重なりが最大または同率。
- 864行（12.0%）: 別椎体maskとの重なりの方が大きい。
- 109行（1.5%）: C1-C7のどのmaskとも重ならない。
- 3,044行（42.2%）、358 / 536 runsでbboxが複数椎体maskにまたがる。
- 64 / 536 runsは別椎体mask優勢の要確認候補、2 runsは全bboxが全maskと無重複。

TotalSegmentator maskも手動GTではないため、上記を自動的な再割当根拠にはしない。
元DICOM・割当椎体mask・元CSV bboxを同時表示し、人が解剖学的にR1-R4を判定する
今回の方式を優先する。
