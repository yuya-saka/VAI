# 3D面としての線学習 — 設計検討（実測ベース）

Date: 2026-07-30
Status: 検討中（未承認・未実装）
関連: `data_preprocessing/learning_dataset/propagate_lines_z.py`, `Unet/multitask/`

---

## 0. 出発点

現状はスライス単体で4本の線を推定している。複数スライスの線を重ねて「面」と定義し、
3D方向に滑らかな推定にすることで、外挿時も構造を保てるのではないか、という提案。

以下はすべて実データ（`data/dataset` 手動アンカー 1,618枚 / `data/dataset_zprop` 21,507枚 /
既存2Dモデルのテスト予測 6,473本線）から測った数値に基づく。

---

## 1. 前提条件の確認：スタックは3Dとして整合しているか → YES

`data_preprocessing/segmentation_dataset/extract_slices.py` の `extract_oblique_slice()` は、
**椎体ごとに1組の傾き (rx, ry) とボリューム中心**を使い、`k` だけを変えて断面を切り出す。
スライスごとの再センタリングや再回転は行っていない。

したがって1椎体のスライス群は単一の剛体フレームを共有し、画像座標のまま z 方向に積めば
正しい3Dボリュームになる。**面を定義する前提は満たされている。**

ボクセルは 0.4mm 等方。よって「1スライス移動あたりの px 変化」＝ tan(面の傾斜角) がそのまま使える。

---

## 2. 実測1：面はスライスに直交しない

各椎体・各線について (φ, ρ) を z の関数として取り、傾斜角 = arctan(dρ/dz) を測った。

| | median | p90 | max |
|---|---|---|---|
| line_1 | 17.0° | 45.2° | 85.2° |
| line_2 | 21.4° | 47.0° | 74.2° |
| line_3 | 17.5° | 42.2° | 86.6° |
| line_4 | 23.2° | 50.2° | 73.1° |

傾きの標準誤差は約3.8°（残差RMS 0.7px、n=11、z幅11から算出）なので、
median 約20°の傾斜はノイズではなく実在する。

**結論：直交拘束（ρ を z に対して一定）を課してはいけない。斜めを許す必要がある。**

---

## 3. 実測2：面は「線織面」であり、3Dボクセルで学習する必要はない

各スライスの境界が直線という現行の前提を保つ限り、面は自動的に線織面（ruled surface）になる。
つまり面 S_c は

```
S_c = { (x, y, z) : x·cos φ_c(z) + y·sin φ_c(z) = ρ_c(z) }
```

と、**z の1次元関数2本だけ**で完全に決まる。4本の線でも合計8本の1次元関数。

→ 3D U-Net でボクセル単位に面を塗る必要はない。学習すべきは低次元の曲線パラメータ。
これは計算量・データ量の両面で決定的に有利（椎体数284しかない）。

---

## 4. 実測3：面の次数は「1次（斜め平面）」が上限

アンカー帯（椎体中央の約4.4mm、11スライス）内で leave-one-slice-out 比較：

| モデル | φ誤差 median / p90 | ρ誤差 median / p90 |
|---|---|---|
| 定数（直交面） | 2.27° / 4.93° | 1.51px / 4.07px |
| **1次（斜め平面）** | **1.80° / 5.29°** | **1.20px / 4.11px** |
| 2次（曲面） | 1.77° / 7.32° | 1.15px / 5.89px |

2次は median がわずかに良いだけで p90 が大幅に悪化＝過学習。
**4.4mmの帯からは曲率を推定できない。** 局所的には1次まで。

一方 z伝播後の椎体全体（median 28mm）で見ると、全域を1本の直線で近似した残差は
φ 5.5〜7.8° RMS、ρ 10〜12px RMS と大きい。つまり椎体全体では明確に曲がる。
ただしこの曲率は伝播モデルが生成したものなので、実測の裏付けはない（後述のリスク参照）。

**設計含意：局所は1次、全体は曲がる。よって曲率は「スラブごとのフィット」ではなく
椎体全体を見る大域的な基底＋事前分布で入れるべき。**

---

## 5. 実測4：4本の線は連動していない。ただし junction は極めて滑らか

椎体をまたいだ dφ/dz の線間相関行列はほぼゼロ（-0.23〜0.02）。
共通成分 std 0.275 °/slice に対し線ごと残差 std 0.664 °/slice。
→ 椎体全体のねじれのような単一の大域変換では表せない。線ごとの自由度が必要。

一方、junction（line_1∩line_2, line_3∩line_4）の z 方向 leave-one-out 予測誤差は
1次で median 1.08px / p90 2.53px。2直線の交点はノイズを増幅するはずなのにこの安定性は、
junction が実在の安定なランドマークであることを示す。

**設計含意：`propagate_lines_z.py` が既に使っている
「junction 2点 + 各線の doubled-angle 4個 = 12次元の状態ベクトル」は、
実測に裏付けられた良いパラメータ化。これを踏襲すべき。**

---

## 6. 実測5（最重要）：z方向の平滑化では精度は上がらない

既存2Dモデルのテスト予測を、椎体×線ごとに z の1次/2次でフィットし直して GT と比較した。

| | 生の予測 | z 1次平滑化後 | z 2次平滑化後 |
|---|---|---|---|
| 角度誤差 median | 3.66° | 3.62° | 3.63° |
| ρ誤差 median | 2.80px | 2.85px | 2.86px |

**ほぼ変化なし。ρ に至っては悪化。**

理由は予測自身のブレを測ればわかる。予測の1次フィットからの乖離は
角度 0.65° / ρ 0.40px（median）しかない。**現行2Dモデルの出力は既に z 方向に十分滑らか**である。
0.4mm間隔の隣接スライスはほとんど同じ画像なので、独立なノイズが乗りようがない。

さらに誤差を分解すると：

| | 椎体×線ごとのバイアス | 帯内のばらつき |
|---|---|---|
| 角度 | median 3.03° / RMS 5.23° | median 1.74° / RMS 3.50° |
| ρ | median 2.73px / RMS 6.24° | median 1.19px / RMS 6.11px |

誤差の主成分は**椎体ごとの系統的バイアス**であり、z方向の平滑化で消える種類のものではない。

> **したがって「複数スライスにまたがる面として滑らかに学習する」ことそれ自体は、
> アンカー帯内の精度には効かない。この期待は実測で否定される。**

---

## 7. では面学習の価値はどこにあるか

否定されたのは「平滑化による精度向上」だけであり、面という定式化自体は依然として有望。
価値は以下の2点に限定される。

### (a) 外挿（本丸）

`data/dataset_zprop` の内訳：

| 種別 | スライス数 | 割合 |
|---|---|---|
| manual | 1,618 | 7.5% |
| interpolated | 362 | 1.7% |
| **extrapolated** | **19,527** | **90.8%** |

アンカーは椎体中央の約3.6mmに集中し、そこから上下 ±11mm を手作りの幾何モデルで外挿している。
`batch_report.json` の leave-one-out 検証（角度誤差0.93°、region Dice 0.99）は
**すべてアンカー帯内＝内挿の検証**であり、外挿の妥当性は一切検証されていない。

学習ベースの面推定なら、帯外のスライスでも画像を実際に見て判断できる。
現行の外挿は画像を一切見ていない（アンカーの傾向を延長しているだけ）。ここが最大の差分。

### (b) z文脈によるバイアス解消

6節の系統的バイアスは、単一の0.4mmスライスでは曖昧さが解けないことに起因する可能性が高い。
椎体全体（±14mm）を文脈として与えれば決まるかもしれない。
これは「平滑化（正則化）」ではなく「情報を増やす」話であり、機構が違う。

## 8. アーキテクチャ案

| 案 | 内容 | 評価 |
|---|---|---|
| A | 2.5D入力 + z平滑化損失 | 平滑化部分は無意味（6節）。ただし2.5D入力による文脈増加は(b)に効く可能性 |
| B | 椎体まるごと3Dエンコーダ → 面係数を直接回帰 | 外挿が構造的に保証される。出力は数十次元なので284椎体でも可能性あり |
| **C** | **現行2D枝を維持 + 微分可能な面フィット頭部 + 整合損失** | **推奨**。局所証拠を捨てずに大域構造を入れられる |
| D | 3D SDF で陰関数曲面 | 直線事前分布を捨てるため却下。データ量的にも無理 |

### 推奨：C を先に、その後 B

**C の構成案**

- 入力：現行通り（CT + mask）に隣接スライスを追加した 2.5D
- 2D枝：現行のヒートマップ + (φ, ρ) 頭部をそのまま維持
- 面頭部：椎体内の全スライスの予測から、12次元状態ベクトル s(z) の
  低次基底係数（正規化 t ∈ [-1,1] 上のB-spline制御点3〜4個）を微分可能にフィット
- 損失：
  - 帯内 → 面から再構成した線と手動GTの一致
  - 帯外 → 2D枝のヒートマップ応答と面の一致（画像駆動の自己教師）
  - 傾斜 |dρ/dt| に実測分布（2節）由来の事前分布

**採用すべき拘束**
- 斜めを許す（直交拘束は禁止：2節）
- junction を経由したパラメータ化（5節）
- z正規化 t = (z - z_center)/(z_extent/2)。椎体の z 幅は 17〜55mm とばらつくため必須

**採用すべきでない拘束**
- 全体を1枚の平面にする（椎体全体では曲がる：4節）
- 4本の線を単一の大域変換で連動させる（相関ゼロ：5節）
- スラブ単位での2次以上のフィット（過学習：4節）

## 9. 最大のリスクと、着手前にやるべきこと

**帯外には手動GTが1枚も存在しない。**

これは二重の問題を生む。

1. **学習できない**：zprop の擬似ラベルで学習すれば、`propagate_lines_z.py` の外挿バイアスを
   そのまま模倣するだけで、教師を超えられない。「構造を保った外挿」を主張する根拠にならない。
2. **評価できない**：外挿が改善したかどうかを測る物差しが無い。

加えて、帯外では**そもそも各スライスの境界が直線で表せるのか**が未検証。
椎体の上下端では終板や椎弓根との移行部に入るため、直線仮定自体が崩れる可能性がある。
これも帯外GTが無いと判定できない。

### 着手前の必須ステップ

1. **帯外の手動アノテーションを少数取る**
   例：椎体数40〜60について、正規化 t = ±0.5, ±0.8 付近の各2〜4枚 → 新規300〜700枚。
   まずここに投資しないと、以降の設計判断がすべて根拠を失う。
2. **その帯外GTで既存の幾何外挿を検証**し、ベースラインを確定する。
   幾何外挿が既に十分正確なら、学習ベースに置き換える意味は小さい。
3. その結果を見てから案Cの実装可否を決める。

## 10. まとめ（前半）

- 面は**斜め**（median約20°）。直交拘束は誤り。
- 面は**線織面**なので、3Dボクセル学習は不要。z の1次元関数を学べばよい。
- 局所は1次まで。曲率は椎体全体の大域基底で入れる。
- **z方向の平滑化そのものは精度に効かない（実測で否定）。**
- 面学習の価値は**外挿**に限定される。

# 第2部：外挿を正しくするための学習方法

目的を「帯内の精度向上」ではなく「**帯外、特に横突孔まわりで境界線が正しく形成されること**」に置いた場合の設計。
GTによる定量評価は行わない前提。

---

## 11. 現行外挿の失敗を目視で確認した

`sample1/C4`（アンカー帯 z=49-56、全域 z=17-89）で伝播線を CT に重ねた。

| z | provenance | confidence | 状態 |
|---|---|---|---|
| 52, 56 | manual | 1.00 | 4本が椎体まわりに正しく配置 |
| 64 | extrapolated | 0.45 | 赤線が右上に飛び出し始める |
| 72 | extrapolated | 0.20 | 緑・黄が右下へ約45°で暴走、画像外へ |
| 80 | extrapolated | 0.10 | 完全に破綻。領域マスクも中央が未割当になる |

角度と junction のトレンドを12mm延長する過程で誤差が累積し、線が椎体から離れていく。
**現行外挿は画像を一切見ていない**ため、破綻しても自己修正の手段がない。

## 12. 横突孔は追加アノテーションなしで検出できる

椎体マスクは中身が埋まっているため、横突孔はマスクの穴としては取れない（87%のスライスで穴ゼロ）。
一方 **CT濃度から取れる**：マスク内部の低濃度連結成分のうち最も外側の左右2つを取ると、

| | 帯内 | 帯外 |
|---|---|---|
| 2個以上検出 | 100% | 74.8% |

目視確認したところ、最外側blobは確かに左右の横突孔に乗る（ただし椎体海綿骨の低濃度部を大量に拾うノイズが多く、
このままでは実用に足りない。学習ベースの検出器にすべき）。

さらに、手動アンカー866枚で **junction と横突孔の位置関係**を測った（横突孔間距離で正規化、median 113.6px）：

| 成分 | 全体std | 椎体間std | 椎体内std | px換算 |
|---|---|---|---|---|
| 左J u | 0.069 | 0.045 | 0.051 | 5.8px |
| 左J v | 0.112 | 0.075 | 0.085 | 9.7px |
| 右J u | 0.082 | 0.054 | 0.061 | 6.9px |
| 右J v | 0.099 | 0.067 | 0.076 | 8.6px |

椎体内 std が junction 自体の帯内変動（約1px）より大きいのは、粗い閾値検出器のノイズが支配的なため。
それでも **6〜10px の精度で全 z に足場が立つ**。12mm 盲目外挿の破綻（数十px〜画像外）に比べれば桁違いに良い。

---

## 13. 決定的な観察：横突孔と椎体を分けるのが line_1 / line_3

`sample1/C4` z=52 の線配置を見ると、

- 緑(line_3)・赤(line_1) はほぼ垂直で、**椎体と左右の横突孔の間の狭い回廊**を通る
- 黄(line_4)・青(line_2) は junction から後外側へ伸びる
- junction は椎体の後外側コーナー、すなわち横突孔のすぐ内側

つまり「横突孔まわりで境界線ができる」という要求は、幾何的には

> **line_1 と line_3 が、椎体（body領域）と横突孔（left/right_foramen領域）を反対側に分離すること**

と言い換えられる。これは GT なしで判定できる条件であり、**そのまま損失にできる**。ここが本設計の要。

なお領域名（body / right_foramen / left_foramen / posterior）は既存パイプラインの定義そのもので、
横突孔領域は最初から独立領域として扱われている（16節）。

## 14. 帯外で使える教師信号は4種類しかない

帯外には手動GTが無いので、以下だけが利用可能。

### (S1) 構造的妥当性（本命・最も強い）

4本の線がマスクを分割した結果に対し、GTなしで検証できる解剖学的条件を損失化する。
線までの符号付き距離を sigmoid に通して soft 領域割当を作れば全て微分可能。

- **横突孔と椎体本体が line_1 / line_3 の反対側にある**（13節。最重要）
- 脊柱管が後方領域（黄）側にある
- 4領域すべてが非空で、面積比が妥当な範囲
- junction がマスク内部にある
- 領域体積が z 方向に連続

これは**全帯外スライスに密な信号を与える**。しかも要求そのものを直接最適化している。

### (S2) 3D等価性（consistency）

面は volume の性質であり、スライスの切り方に依らない。
入力ボリュームをランダムに3D回転して再スライスし、予測面を逆変換して一致を要求する。
ラベル不要で全 z に効き、「スライス面のアーティファクトに依存した予測」を排除する。

ただしこれが保証するのは*一貫性*であって*正しさ*ではない。単独では不十分。

### (S3) 帯内ホールドアウトによる外挿の訓練

アンカー帯の外側スライスを教師から落とし、内側だけを見せて復元させる。
外挿距離は±2mm程度で実際の±12mmには遠いが、
**「画像を見て外挿する」という振る舞いそのものを訓練できる唯一の教師あり信号**。

### (S4) zprop 擬似ラベルを「事前分布」として弱く使う

`line_provenance.json` に confidence（帯内1.0、帯外0.45/0.20/0.10）が既に入っている。
これを重みにした弱い引力項として使う。**正解としてではなく、暴走を防ぐ錨として**使うのがポイント。
重みを上げすぎると既存外挿のバイアスを丸ごと模倣して終わる。

## 15. 推奨アーキテクチャ

### 表現

椎体ごとに、正規化 t ∈ [-1,1] 上の状態ベクトル

```
s(t) = [ J_R(t) (2), J_L(t) (2), 4本の doubled-angle (8) ]   = 12次元
```

を制御点5個のB-splineで表す（計60パラメータ）。5節の実測（junctionは滑らか・線間は非連動）に基づく。
z正規化は必須（椎体のz幅は17〜55mmとばらつく）。

### ネットワーク

- 入力：椎体ボリューム全体（CT + マスク、面内128に縮小、z は原寸）
- 3Dエンコーダ（軽量）→ 60個の制御点を回帰
- 2D枝（現行のヒートマップ頭部）は残し、帯内の精度と、横突孔・脊柱管の検出に使う

### 損失

| 項 | 適用範囲 | 役割 |
|---|---|---|
| アンカー再構成 | 帯内 | 唯一の真の教師 |
| 帯内ホールドアウト (S3) | 帯内 | 外挿の振る舞いを訓練 |
| 構造的妥当性 (S1) | **全 z** | 帯外の主教師。横突孔分離を含む |
| 3D等価性 (S2) | 全 z | 一貫性 |
| zprop事前分布 (S4) | 全 z・低重み | 暴走防止の錨 |
| 傾斜の事前分布 | 全 z | \|dρ/dt\| を実測分布（2節）で抑制 |

## 16. 定量評価はできる（GT不要の指標が既に目的と一致している）

「定量評価はできない」というのは GT との比較に限った話で、
**領域が形成できたか否かは GT なしで測れる**。そしてそれが目的そのものである。

しかも `data/dataset_zprop/local_correction_qc_summary.json` に既に記録があり、
4領域の名前は **body / right_foramen / left_foramen / posterior**。
つまり左右の横突孔領域は独立した領域として定義済みで、その消失が記録されている。

`gt_masks` から全 21,507 スライスを再集計した結果：

| | スライス数 | 領域欠損 |
|---|---|---|
| 帯内（manual/interpolated） | 1,980 | **0 (0.0%)** |
| 帯外（extrapolated） | 19,527 | **2,814 (14.4%)** |

欠損の内訳（帯外）：

| 領域 | 面積0のスライス | 率 |
|---|---|---|
| **right_foramen** | 1,423 | **7.3%** |

cubic spline 伝播のはずが、この粗さは異常。帯内GTの LOO 残差（1.8°/1.2px）と比べても桁が違う。
面として定式化すれば、この非平滑性は構造的に排除される。

## 17. 最も価値の高い可視化：z軸を含む断面へのリフォーマット

面 `x cosφ(z) + y sinφ(z) = ρ(z)` を、z軸を含む任意の平面（矢状断・冠状断）で切ると、
交線は **z ごとに1点の曲線**になる。つまり

> **矢状断・冠状断のリフォーマット画像上では、各境界面は1本の曲線として全高にわたって見える。**

現行のスライスごとの overlay では絶対に見えない「面が椎体全高でどう走っているか」が、
1枚の画像で判定できる。アンカー帯はその曲線の短いセグメントとして写る。

定量評価ができない以上、**これが実質的な評価手段**になる。しかも学習不要ですぐ作れる。

さらに発展させるなら、この視点は評価だけでなく**学習の定式化そのもの**になりうる：
リフォーマット面上では外挿方向が面内方向になるため、
「盲目的なパラメータ外挿」が「画像中の構造を面内で延長する」という、
CNNが得意でかつ画像証拠に駆動される問題に変わる。

## 21. 面の定義（スラブ内）

![面の定義](line-surface-explain.png)

### ρ は使わない（2026-07-30 決定）

面を (φ, ρ) で表すのをやめ、**(角度, ヒートマップ重心)** で表す。

理由は2つ。

1. **ρ は派生量である。** `utils/losses.py:199` を見ると
   `rho = (nx*cx + ny*cy) / D`。つまり ρ は重心 (cx, cy) を法線方向に射影しただけで、
   **線に沿った方向の情報を捨てている**。一次情報は重心の方。
2. **評価で見るのは角度誤差と重心誤差**であり、パラメータをそれに合わせるべき。

副次的な利点として、ρ を捨てると φ の巻き戻り問題（後述）が構造的に消える。

### 手順

1. **1枚のスライスでの線 = 角度 α + 重心 (cx, cy)**
   どちらも `_compute_moments_batch` が既に返している（`nx, ny, cx, cy`）。新規実装不要。
2. **N枚重ねる**
   スラブ15枚なら line_1 について15組。現在はこれを各スライス独立に予測している。
3. **積むとリボンになる**（図①）
   各スライスの線分を高さ z に置いて積むと、ねじれた細長い帯（リボン）ができる。
   赤が線分、青が重心の軌跡＝**リボンの背骨**。
   「面」といっても無限に広がった曲面ではなく、この帯を指す。
4. **z の1次で表す**

線1本につき、次の4量をそれぞれ z の1次で表す：

```
cx(z)     = cx0    + u·Δz
cy(z)     = cy0    + v·Δz
cos 2α(z) = p0     + p1·Δz          Δz = z - スラブ中心
sin 2α(z) = q0     + q1·Δz
```

= **8個の係数**。4本の線で合計32個でスラブの全構造が決まる。

| 係数 | 意味 |
|---|---|
| cx0, cy0, α0 | スラブ中央での線分の位置と向き（＝真ん中の1枚そのもの） |
| **u, v** | 1スライス進むごとに重心が何px動くか → **リボンの傾き** |
| **p1, q1** | 1スライス進むごとに何度回るか → **リボンのねじれ** |

角度を doubled-angle の2成分に分けて別々に1次フィットするのがポイント。
こうすると周期の巻き戻りを一切扱わずに済む（フィット後に正規化して `α = atan2(q,p)/2`）。

### 1次で良いことの実測（重心座標で再検証）

GTヒートマップを実際に生成して重心と主軸角を取り、椎体×線 708件で測り直した。

帯内（median 2.8mm）での実際の動き：

| | median | p90 |
|---|---|---|
| 重心の移動量 | 4.38 px | 7.46 px |
| 角度の変化量 | 5.61° | 12.07° |

leave-one-slice-out：

| モデル | 重心誤差 px (median/p90) | 角度誤差 deg (median/p90) |
|---|---|---|
| 定数 | 1.78 / 3.12 | 2.34 / 5.03 |
| **1次** | **1.50 / 2.88** | **1.95 / 5.39** |
| 2次 | 1.65 / 4.20 | 1.96 / 7.41 |

**1次が最良**。定数から1次で重心が16%、角度が17%改善し、2次は p90 が悪化して過学習する。
(φ, ρ) で測ったとき（4節）と同じ結論。

図②③は実データ（sample3/C5、20枚=8mm）。角度も重心も z の直線に乗る。

### 何が変わるか

| | 現在 | 面として学習 |
|---|---|---|
| 出力 | 15枚 × 3個 = 45個を独立に予測 | 8個を予測 |
| 保証 | 出力がリボンである保証がない | **出力が必ずリボンになる** |

「各スライスで線を当てる問題」が「リボンを1本当てる問題」に変わる。

### 参考：ρ を使った場合に踏む地雷

φ は [0°, 180°) の周期なので、線が 0/180° をまたぐと φ が飛ぶと同時に **ρ の符号が反転する**。
実際に sample3/C5 で踏んだ：素朴なフィットでは ρ が -22px と +23px を往復し、
傾きが -1.01px/slice（傾斜45°）と誤って出た。正しくは +0.12px/slice（7°）。
帯内で φ が 0/180° をまたぐ椎体×線は **42/1108 件（3.8%）、38椎体**。

重心 + doubled-angle 表現ならこの問題は最初から発生しない。

## 22. モデルと損失（既存を壊さない最小変更）

### 最小構成

`ResUNet` は `in_channels` / `line_channels` が config 引数なので、

- 入力：`in_channels = 2N`（CT + マスク を N スライス分チャンネル方向に積む）
- 出力：`line_channels = 4N`（4本 × N スライス分のヒートマップ）

とするだけで 2D のままスラブを扱える。3D conv 化は次段階でよい。

### 微分可能なリボンフィット

1. 各スライスの予測ヒートマップから `_compute_moments_batch` で
   **重心 (cx, cy) と法線 (nx, ny)** を取る（既に実装済み。`rho` の計算行は使わない）
2. 角度は doubled-angle に直す：`cos2α = nx²-ny²`, `sin2α = 2·nx·ny`
3. 4量 `[cx, cy, cos2α, sin2α]` をスラブ全体で **z の1次回帰**（閉形式・微分可能）
   → 線1本あたり8係数、4本で32係数

新しい回帰ヘッドを足さないのがポイント。
直接パラメータ回帰は過去に不安定だった形跡がある（config の `use_line_loss: false`）ため、
実績のあるヒートマップ経路を残す。

### 損失

| 項 | 適用 | 中身 |
|---|---|---|
| 既存ヒートマップ損失 | ラベルのあるスライスのみ | 局所証拠 |
| **角度損失** | ラベルのあるスライス | フィット値の (cos2α, sin2α) vs GT の L2 |
| **重心損失** | ラベルのあるスライス | フィット値の (cx, cy) vs GT の px 距離 |
| **リボン外れ罰** | スラブ全スライス | 各スライスの生の4量とフィット値の差 |

角度損失と重心損失が、そのまま**評価指標そのもの**（角度誤差・重心誤差）になっている。
「リボン外れ罰」だけはラベル不要なので全スライスに掛かり、これが面としての一体性を作る。

なお線分の長さもモデル化するなら5番目の量として足せる（現行 CSV に `pred_length` がある）。
まずは無しで始めてよい。

## 24. 推論：長距離外挿が不要になる

椎体全高をスラブでスライディング（stride 1〜3）し、各位置で局所の面パッチを出す。
重なりを平均して大域の面にする。

**これが本質的な改善点**：現行は3.6mmのアンカー帯から ±12mm を画像を見ずに外挿している。
スライディングなら各位置で実際の画像を見るので、**外挿距離は常に窓の半分（3〜4mm）以内**に収まる。
21節で1次が最適と確認した範囲そのもの。

重なり位置での予測の不一致は、そのまま **GT不要の信頼度指標**になる。
